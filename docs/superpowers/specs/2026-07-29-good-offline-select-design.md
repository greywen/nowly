# Good 离线 Select 设计规格

## 1. 目标

为 Nowly 建立一个无第三方运行时依赖的 React 单选组件，复刻 Good Select2 的视觉语言，并接入任务与日程弹窗。组件支持普通单选和可搜索单选，遵循项目统一设计规范、无动效要求与 WAI-ARIA Combobox/Listbox 交互模式。

本次不引入 jQuery、Select2、Radix UI 或 React Aria，不修改 HTML 原型、设置弹窗和数据持久化逻辑。

## 2. 组件架构

新增一个可复用 `Select` 组件。组件采用受控 API，主要输入包括：

- 可访问标签或标签关联信息；
- 选项数组；
- 当前值；
- 值变更回调；
- 占位文字；
- 是否启用搜索；
- 是否禁用；
- 可选的“无关联”空值项。

每个选项包含稳定值和显示文字。可见控件由 Combobox 触发器和 Listbox 浮层组成；同时保留隐藏表单输入以支持标准表单提交。组件内部只管理展开状态、搜索词和键盘高亮项，不拥有业务选择值。

组件保持单一职责：Select 负责选择与无障碍交互，任务和日程弹窗负责提供业务选项及保存本地表单状态。

## 3. 业务接入

### 3.1 任务弹窗

任务弹窗新增并接入：

- 所属象限：普通单选；
- 优先级：普通单选；
- 关联日程：可搜索单选，可选择“无关联”。

象限默认值由当前任务象限推导。优先级和关联日程在现有模型缺少对应字段时使用明确的演示默认值。关联日程选项来自现有 `sampleEvents`。

### 3.2 日程弹窗

日程弹窗新增并接入：

- 分类：普通单选；
- 关联任务：可搜索单选，可选择“无关联”。

关联任务选项来自现有 `sampleTasks`。分类在现有模型缺少字段时使用明确的演示默认值。

### 3.3 状态边界

选择结果保存在各弹窗本地状态中。点击保存不扩展当前持久化能力，也不修改领域模型。弹窗关闭后，本地选择状态、Select 展开状态和搜索词全部销毁。

## 4. 视觉规格

组件严格复用 `design.md` Token：

- 触发框高度 `48px`；
- 背景 `#F8F6F2`；
- 默认边框透明，聚焦或展开时边框 `#4FC9DA`；
- 圆角 `15.2px`；
- 水平内边距 `16px`；
- 文字 `16px / 400 / 1.5`，颜色 `#716D66`；
- 占位文字颜色 `#968E7E`；
- 右侧图标采用 Lucide `ChevronDown`；
- 键盘焦点环为 `0 0 0 4px rgba(79, 201, 218, 0.25)`。

下拉面板使用：

- 白色背景；
- `15.2px` 圆角；
- `0 0 50px 0 rgba(82, 63, 105, 0.15)` 阴影；
- 选项 hover 背景 `#F8F6F2`；
- 当前项背景 `#DDF8FC`、文字 `#30A6B6`，并显示 Lucide 勾选图标；
- 搜索框沿用 Good Solid 输入样式；
- 无结果状态文字为“未找到匹配项”。

所有展开、关闭、聚焦、选中和过滤状态即时变化。组件不得包含 `transition`、`animation`、平滑滚动或 JS 补间动画。

## 5. 浮层定位

下拉面板相对触发器定位，宽度至少与触发器一致。默认向下展示；下方空间不足时向上展示。面板宽度和高度受视口及业务弹窗可见区域约束，不覆盖弹窗 Header，也不越出弹窗左右边界。选项较多时仅列表区域滚动。

定位只在打开和必要的窗口尺寸变化时计算，不引入连续动画或自动滚动。

## 6. 交互规则

### 6.1 指针操作

- 点击触发器展开或关闭；
- 点击选项后更新值并关闭；
- 点击组件外部关闭；
- 禁用状态不能展开；
- 可搜索模式打开后可直接输入搜索词；
- 搜索采用不区分英文大小写的文字包含匹配，同时自然支持中文文本；
- 无匹配结果时显示静态空状态。

### 6.2 键盘操作

- `Enter` 或 `Space`：打开，或选择当前高亮项；
- `ArrowDown` / `ArrowUp`：打开并移动高亮项；
- `Home` / `End`：移动到首项或末项；
- `Escape`：关闭并把焦点归还触发器；
- 普通单选支持按文字前缀定位选项；
- 可搜索单选通过搜索输入过滤选项；
- 选择完成后焦点回到触发器。

## 7. 无障碍

- 触发器使用 `role="combobox"`；
- 提供 `aria-expanded`、`aria-controls` 和 `aria-haspopup="listbox"`；
- Listbox 使用 `role="listbox"`；
- 每个选项使用 `role="option"` 和正确的 `aria-selected`；
- 键盘高亮项通过 `aria-activedescendant` 暴露；
- 搜索输入具有明确可访问名称；
- 字段标签与 Combobox 建立程序化关联；
- 禁用状态使用原生 `disabled` 或等效 ARIA，并阻止交互；
- 当前选择除颜色外同时通过勾选图标和 `aria-selected` 表达。

## 8. 错误与边界处理

- 当前值不在选项中时显示占位文字，而不是渲染无效文本；
- 空选项数组显示“暂无可选项”；
- 搜索过滤后无结果显示“未找到匹配项”；
- 关联选择提供“无关联”项用于清除；
- 选项变化导致高亮项失效时，高亮回退到当前已选项或首个可用项；
- 多个 Select 同时存在时，打开新 Select 不依赖全局状态；点击其他区域会关闭原浮层。

## 9. 测试策略

采用 Vitest、Testing Library 和现有测试环境，先编写失败测试再实现。

组件测试覆盖：

1. 普通单选的初始值、展开和选择；
2. 可搜索单选的过滤和“未找到匹配项”；
3. 空选项状态；
4. `ArrowUp/Down`、`Home`、`End`、`Enter`、`Space` 和 `Escape`；
5. 点击外部关闭与焦点归还；
6. `role`、`aria-expanded`、`aria-selected` 和活动选项状态；
7. 禁用状态；
8. 不存在 CSS `transition` 或 `animation`。

业务测试覆盖：

- 任务弹窗呈现象限、优先级和可搜索关联日程；
- 日程弹窗呈现分类和可搜索关联任务；
- 选项来源使用现有示例数据；
- 选择操作更新弹窗本地显示值。

最后运行完整单元测试和构建，确认没有回归。

## 10. 验收标准

- 项目拥有一个可复用、无第三方运行时依赖的 React Select；
- 普通与可搜索单选均可通过鼠标和键盘完整操作；
- 任务和日程弹窗按本规格接入业务字段；
- 组件视觉符合 Good Select2 及 `design.md`；
- 浮层不越出业务弹窗和视口可见边界；
- 无动效、无 jQuery、无 Select2、无 CDN；
- 无障碍语义和自动化测试通过；
- 不修改数据持久化、设置弹窗或 HTML 原型。
