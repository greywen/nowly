# 日历时区统一（RFC 5545 模型）设计

## 目标

把 Nowly 日历从「不带时区的钟面时间」升级为与 iCal / Google 日历 / Apple 日历一致的
**per-event 时区模型**，作为后续「日历订阅」功能的地基。升级后，事件的时间语义由「钟面
时间 + 时区归属」共同决定，三种时间形态并存：

- **定时事件** = 钟面时间 + 具名 IANA 时区（如 `Asia/Shanghai`），跨时区时显示为对应的
  当地钟点（绝对时刻不变）。
- **浮动事件** = 只有钟面时间、时区为 `NULL`，在任何时区都按本机时区显示同一个钟点。
- **全天事件** = 只有日期，时区无关。

显示层第一版**跟随设备当前时区**：机器时区变化时，带时区事件的显示钟点随之换算（绝对
时刻锚定不变），浮动事件与全天事件的钟面 / 日期保持不变。

## 范围

本项目**做**：

- `events` 表新增时区列与 UTC 缓存列，配套数据迁移。
- 时区换算层（引入 `chrono-tz`）。
- 重复事件在具名时区下的展开与 DST 边界处理。
- 范围查询适配（浮动/全天走钟面比较，带时区走 UTC 缓存比较）。
- 提醒触发时刻按时区正确计算。
- 前端 `CalendarEvent` 模型与渲染适配（带时区事件按设备时区显示钟点）。

本项目**不做**（留待后续，且不破坏本项目的存储模型）：

- 本地编辑弹窗的时区选择器：本地新建 / 编辑的事件一律为浮动事件。
- 显示时区覆盖开关（Apple「时区覆盖」式的 power-user 功能）。
- 日历订阅功能本身（下一个独立项目，其决策见文末「后续项目衔接」）。

## 存储模型

真值语义永远是「钟面时间 + 时区」，UTC 列仅为查询 / 索引缓存。

`events` 表新增列：

- `start_tz TEXT` / `end_tz TEXT`：具名 IANA 时区标识；`NULL` 表示浮动事件。全天事件同样
  为 `NULL`（时区无关）。
- `start_utc TEXT` / `end_utc TEXT`：预计算的 UTC 瞬时点缓存，格式 `%Y-%m-%dT%H:%MZ`。
  **仅对带时区（`start_tz IS NOT NULL`）的定时事件有值**；浮动事件与全天事件为 `NULL`。
  由 `start_at + start_tz` 经 `chrono-tz` 换算得出，写入路径负责维护其与钟面列一致。

`start_at` / `end_at` 的含义不变，仍是钟面时间字符串（`%Y-%m-%dT%H:%M`，全天为日期）。

`event_exceptions` 表**不新增时区列**：一次改期（override）不改变所属系列的时区归属，
override 的 `start_at` / `end_at` 继承系列的 `start_tz` / `end_tz`。展开时按系列时区解释
override 的钟面时间。

重复列（`recurrence_until`、`recurrence_final_at`）仍是系列时区下的钟面时间，不单独存
时区。

## 数据迁移

新增一个迁移（编号顺延现有迁移序列）：

1. `ALTER TABLE events ADD COLUMN start_tz TEXT`（默认 `NULL`）。
2. `ALTER TABLE events ADD COLUMN end_tz TEXT`（默认 `NULL`）。
3. `ALTER TABLE events ADD COLUMN start_utc TEXT`（默认 `NULL`）。
4. `ALTER TABLE events ADD COLUMN end_utc TEXT`（默认 `NULL`）。

所有现存事件迁移后 `start_tz` / `end_tz` = `NULL`，即**全部视为浮动事件**，钟面时间原样
保留。这是唯一诚实的选择：老数据本就不带任何时区信息，标为浮动使显示钟点完全不变，
用户无感知，也不引入错误的时区假设。UTC 缓存列对浮动事件为 `NULL`，无需回填。

配套索引：为 `start_utc` 建索引以支撑带时区事件的范围查询：

```sql
CREATE INDEX IF NOT EXISTS idx_events_start_utc ON events(start_utc)
  WHERE start_utc IS NOT NULL;
```

现有 `idx_events_range`（`start_at, end_at`）保留，服务浮动/全天事件的钟面范围查询。

## 依赖

Rust 侧新增 `chrono-tz`（IANA 时区数据库），用于具名时区与 UTC / 本机时间的换算。这是
本项目唯一新增依赖。前端不新增依赖：设备时区通过既有运行环境获取，钟点换算在读取事件
时于后端完成后下发，或由前端按下发的 UTC + 设备时区换算（见「前端」一节，采用后端换算
为准的方案）。

## 重复事件与 DST

重复系列存「钟面时间 + 时区」。展开某个 slot 的流程：

1. **在系列时区里按钟面时间递推 slot**：每个匹配日都是「该时区的当地钟面时间」。
   `recurrence.rs` 现有的递推逻辑（在 `NaiveDateTime` 上按规则走）基本不变。
2. **每个 slot 用 `chrono-tz` 换算**：得到 UTC 瞬时点（写入 `start_utc` 缓存 / 参与范围
   判定）与本机显示时间。

DST 边界行为，遵循 RFC 5545 / Google / Apple 的标准：

- **钟面时间恒定**：夏令时切换前后，「每周一 10:00」永远显示 10:00，变化的是其对应的 UTC
  偏移。这是主行为，也是用户直觉。
- **春季跳表中不存在的钟面时间**（如某地 02:30 直接跳到 03:00，02:30 不存在）：顺延到
  断层后的有效时刻，即 `chrono` `LocalResult` 取 **later**。
- **秋季回拨中出现两次的钟面时间**（如 01:30 出现两次）：取**第一次出现**，即取
  **earlier**。
- **浮动重复事件**（`tz = NULL`）：完全不换算，钟面时间在本机时区直接使用，等同现有
  `recurrence.rs` 行为。

## 提醒

提醒偏移（提前 N 分钟）的实际触发时刻 = 该次事件的 UTC 瞬时点 − 偏移：

- **带时区事件**：先由「钟面 + 时区」算出该次的 UTC 瞬时点，再减去偏移。
- **浮动事件**：按本机当前时区把钟面时间解释为瞬时点，再减去偏移。

`reminder_dispatches` 的去重键（`event_id, occurrence_start_at, offset_minutes`）中的
`occurrence_start_at` 仍为系列时区下的钟面 slot，不变。

## 范围查询

日历以「当前设备时区的钟面窗口」发起查询（如八月 = 设备本地 `2026-08-01T00:00` 到
`2026-09-01T00:00`）。查询拆为两条谓词的并集：

- **浮动 / 全天事件**（`start_tz IS NULL`）：直接用钟面时间字符串与窗口比较——即现有
  `list_in_range` 的逻辑，保持不变。
- **带时区事件**（`start_tz IS NOT NULL`）：把窗口两端用**设备当前时区**换算成 UTC 瞬时点，
  用 `start_utc` 缓存列做半开区间比较，走 `idx_events_start_utc` 索引。

带时区的重复系列预筛同理：系列的 `start_utc` / `recurrence_final_at`（换算为 UTC 后）与
窗口的 UTC 边界比较；命中后在系列时区里展开 slot，逐个换算判断是否落窗。

两条谓词各自产出的事件合并后，仍按现有的稳定排序规则排序（`start_at` → `end_at` → `id`
→ `occurrence_start_at`）。排序键改用可比较的绝对时刻（对带时区事件用 UTC，对浮动/全天
事件用本机时区解释后的瞬时点），保证跨形态的时间线一致。

## 前端

换算在后端完成，前端不引入时区库。数据库列与下发字段的语义区分如下：

- **数据库列** `start_at` / `end_at`：事件自身时区下的钟面时间（浮动事件即本机钟面）。
- **下发字段** `CalendarEvent.startAt` / `endAt`：**设备当前时区下的显示钟面**。带时区事件
  由后端读取路径按「事件钟面 + 事件时区 → 设备时区」换算后下发；浮动 / 全天事件二者相同
  （直接用钟面）。前端只负责展示，不做时区运算。
- **下发字段** `CalendarEvent.startTz` / `endTz`（`string | null`）：事件自身的具名时区，
  浮动 / 全天为 `null`。用于详情展示（如「(北京时间)」标注）与调试，不参与月历钟点渲染
  （钟点已由 `startAt` 给出）。
- **重复实例身份** `occurrenceStartAt` 保持在**系列自身时区**下的钟面 slot，不随设备时区
  换算——它是例外表的身份键，换算会破坏与 `event_exceptions` 的匹配。本项目内本地事件
  皆为浮动，系列时区即本机时区，二者一致；订阅事件只读、不编辑，不涉及例外身份。
- **编辑弹窗第一版不加时区字段**：本地新建 / 编辑的事件一律写为浮动（`start_tz` /
  `end_tz` = `NULL`）。存储模型已支持具名时区，将来加时区选择器是纯 UI 增量，不动数据
  结构。
- 详情 / 列表的时区标注为可选增强，不阻塞主功能。

## 兼容性与回归

- 浮动路径 = 旧行为：现存事件全部为浮动，`events.rs` / `recurrence.rs` 的既有测试在浮动
  路径下必须继续全部通过。
- 迁移后钟面时间与显示不变，用户数据无可见变化。
- UTC 缓存列由写入路径统一维护；任何创建 / 更新带时区事件的路径都必须同步重算
  `start_utc` / `end_utc`。

## 测试

Rust 单元测试：

- 时区换算：具名时区钟面 ↔ UTC 的往返换算正确（含非整点偏移时区）。
- DST 春季跳表：不存在的钟面时间顺延到 later 的展开结果。
- DST 秋季回拨：出现两次的钟面时间取 earlier 的展开结果。
- 带时区重复系列跨 DST 切换：钟面 10:00 恒定、UTC 偏移在切换点前后不同。
- 老数据迁移：迁移后事件为浮动、钟面不变、UTC 列为 `NULL`。
- 范围查询：带时区事件按设备时区窗口正确落窗 / 出窗（含跨时区边界的临界事件）。
- 提醒触发时刻：带时区与浮动事件分别算出正确的 UTC 瞬时点。
- 回归：`events.rs` / `recurrence.rs` 现有测试在浮动路径下全部通过。

前端组件测试：

- 带时区事件在给定设备时区下显示正确钟点。
- 浮动 / 全天事件显示钟面不变。
- `CalendarEvent` 新字段的序列化 / 反序列化。

## 后续项目衔接（日历订阅，非本项目范围）

本项目完成后，「日历订阅」项目将在此模型上实现，已确认的决策记录如下，供后续 spec 使用：

- 刷新模型：启动时 + 定时 + 手动。定时间隔默认 15 分钟，可设 1–30 分钟。
- 月历样式：实心竖条主体 + 右侧来源徽标区分订阅来源。
- 颜色：每个订阅源一个固定颜色，添加订阅时选定。
- 重复事件：拉取时在窗口内（当前月前后各 6 个月，约 13 个月）展开成具体只读实例。
- 管理界面：Settings 内新增「日历订阅」，采用看板设置的 tab + 列表管理形式。
- 交互：订阅事件可点开只读详情弹窗；不可编辑 / 删除 / 关联任务；移除整个订阅源才消失。
- 订阅源上限：最多 3 个。
- 拉取失败：保留上次成功数据继续显示，在订阅列表标记失败状态与原因，不弹全局报错。
- URL 安全：复用现有 `net.rs` 基线（强制 https、拦截内网 IP、禁止重定向、限制大小、
  超时）；`webcal://` 自动转 `https://`。
- 时区：订阅事件自带具名时区，无损映射到本项目建立的 per-event 时区模型。
