# Nowly 最终 UI/UX HTML 设计规格

日期：2026-07-29

## 1. 目标

为 Nowly 制作一份可作为最终界面实现依据的高保真、响应式 UI/UX HTML 原型。

原型用于确认产品最终视觉呈现，并应满足：

- 忠实采用 Good / Keenthemes 的视觉语言。
- 展示完整、真实的 Nowly 单屏桌面主界面。
- 支持切换浅色渐变背景和桌面融合背景。
- 通过主界面入口或原型控制器查看全部关键弹窗。
- 适配 1366×768、1920×1080 和更高分辨率。
- 单文件直接打开，无需安装依赖或执行构建。
- 聚焦展示级交互，不实现数据持久化或系统级功能。

## 2. 产品与范围约束

Nowly 是 Windows 桌面壁纸型效率面板，而不是传统多页面后台系统。原型必须维持一个固定视口内的单主界面：日历为主体，右侧同时显示四象限任务和便签。

本次范围包括：

1. 完整主界面。
2. 浅色渐变与桌面融合两种背景模式。
3. 日期详情、日程编辑、任务编辑、便签编辑、设置五类弹窗。
4. 展示级界面切换和状态反馈。
5. 响应式布局及无障碍基础状态。

本次不包括：

- SQLite 或其他数据持久化。
- 真实日历 CRUD。
- Tauri、Windows 壁纸嵌入或系统设置调用。
- Good 后台模板的侧栏、面包屑、页面导航和无关装饰。
- 完整业务校验或生产级状态管理。

## 3. 设计基准

### 3.1 参考风格

界面以 Good / Keenthemes Bootstrap Admin Dashboard 为明确视觉参考，提取以下特征：

- 明亮、克制的页面底色。
- 白色或轻透明卡片。
- 蓝色主操作色。
- 柔和阴影和低对比边框。
- 充分留白、清晰的信息层级。
- 统一的线性图标和紧凑但不拥挤的控件。

只采用其视觉体系，不复制后台产品结构。

### 3.2 视觉 Token

- 主色：`#009EF7`
- 主文本：`#181C32`
- 次级文本：`#7E8299`
- 页面底色：`#F5F8FA`
- 边框：`#EFF2F5`
- 成功色：`#50CD89`
- 警告色：`#FFC700`
- 危险色：`#F1416C`
- 紫色辅助色：`#7239EA`
- 卡片圆角：16–20px
- 控件圆角：8–12px
- 字体：Inter、Microsoft YaHei、系统无衬线字体
- 动效时长：150–200ms

图标使用统一线性笔画风格，视觉上对应 Lucide 或 KeenIcons，不使用 Emoji 作为功能图标。

## 4. 页面架构

```text
Nowly Prototype
├─ 背景层
│  ├─ 浅色渐变模式
│  └─ 桌面融合模式
├─ 顶部状态栏
│  ├─ 当前时间与日期
│  ├─ 今日摘要
│  ├─ 背景模式切换
│  ├─ 设置入口
│  └─ 设为壁纸入口
├─ 主内容区
│  ├─ 日历月视图
│  └─ 右侧信息栏
│     ├─ 四象限任务
│     └─ 便签
├─ 弹窗层
│  ├─ 日期详情
│  ├─ 日程编辑
│  ├─ 任务编辑
│  ├─ 便签编辑
│  └─ 设置
└─ 可折叠原型控制器
   ├─ 直接打开各弹窗
   └─ 重置演示状态
```

页面固定为 `100vw × 100vh`，`html`、`body` 和根容器禁止滚动。只允许弹窗主体以及任务、便签等指定内部区域滚动。

## 5. 主界面设计

### 5.1 顶部状态栏

左侧显示三级信息：

1. `09:41`，作为第一视觉焦点。
2. `2026 年 7 月 23 日，星期四`。
3. `今天有 3 个日程 · 2 个重要任务 · 2 条便签`。

右侧显示：

- 浅色背景／桌面融合模式切换。
- 设置按钮。
- “设为壁纸”蓝色主操作按钮。

顶部不是网站导航，不显示菜单或面包屑。

### 5.2 日历主区域

日历是页面最大区域。卡片头部包含：

- `2026 年 7 月`
- `本月 12 个日程`
- 上一月、今天、下一月
- “新建日程”按钮

月视图采用星期一至星期日七列：

- 非当前月日期降低对比度。
- 今天使用淡蓝背景、蓝色描边及实心日期标识。
- 周末使用极轻的区别底色。
- 单日显示 2–3 条日程；超出时显示“还有 N 项”。
- 蓝色表示工作，红色表示重要事项，绿色表示个人生活，紫色表示学习。
- 日程除颜色外还应包含文字或图标线索，避免只依赖颜色表达分类。

点击日期打开日期详情；点击日程打开日程编辑；“新建日程”打开空白日程表单。切月按钮只需要提供展示级月份变化反馈，不更改真实数据。

### 5.3 四象限任务

右栏上半部分标题为“优先事项”，同时展示未完成数量和新增按钮。

四象限采用 2×2 布局：

- 重要且紧急：浅红。
- 重要不紧急：浅蓝。
- 不重要但紧急：浅黄。
- 不重要不紧急：浅灰。

每个象限显示 1–2 个关键任务，包含复选框、标题和截止状态。已完成任务降低透明度并显示删除线。点击任务打开任务编辑；点击复选框只切换原型中的视觉完成状态。

### 5.4 便签

右栏下半部分展示：

- 标题“便签”。
- 新增入口。
- 置顶标识和最近更新时间。
- 两条具有真实标题及内容摘要的便签。
- “查看全部便签”低权重入口。

便签使用柔和黄、蓝色调。点击便签打开便签编辑弹窗。

## 6. 背景模式

### 6.1 浅色渐变模式

使用 `#F5F8FA` 为基础，叠加低饱和蓝色与绿色径向渐变。卡片保持白色、轻边框和柔和阴影，形成稳定的 Good 风格默认外观。

### 6.2 桌面融合模式

使用一幅内嵌或 CSS 构建的抽象桌面壁纸作为演示背景。卡片改为轻透明背景并增加有限的背景模糊，但必须保证文本对比度和可读性。

该模式只改变背景、卡片透明度和阴影，不改变页面信息结构或布局。

## 7. 弹窗设计

所有弹窗遵循：

- 居中显示于遮罩层之上。
- Header 和 Footer 保持可见，Body 可独立滚动。
- 最大高度不超过视口安全区域。
- `Esc`、关闭按钮和点击遮罩均可关闭。
- 打开时将焦点移入弹窗，关闭时返回触发控件。
- 删除为危险操作，取消为次级操作，保存为蓝色主操作。

### 7.1 日期详情

宽度约 520px，包含：

- 日期和星期标题。
- 当日日程时间轴。
- 关联任务摘要。
- “新建日程”和“新建任务”操作。
- 可继续点击日程进入日程编辑弹窗。

### 7.2 日程编辑

宽度约 560px，包含：

- 标题。
- 日期。
- 开始和结束时间。
- 全天事件开关。
- 分类和颜色。
- 关联任务。
- 备注。
- 删除、取消、保存。

字段按基础信息、时间、关联与备注分组。

### 7.3 任务编辑

宽度约 520px，包含：

- 任务标题。
- 四象限可视化选择器。
- 截止日期。
- 优先级。
- 关联日程。
- 完成状态。
- 备注。
- 删除、取消、保存。

四象限使用四张可选状态卡，不使用普通下拉框。

### 7.4 便签编辑

宽度约 500px，包含：

- 标题。
- 大面积内容编辑区。
- 颜色选择。
- 置顶开关。
- 更新时间。
- 删除、取消、保存。

### 7.5 设置

宽度约 720px。左侧设置分类为：

- 外观
- 桌面行为
- 模块显示
- 启动与系统

默认显示“外观”，提供：

- 浅色渐变／桌面融合背景选择。
- 卡片透明度。
- 平衡型信息密度。
- 周起始日。
- 是否显示周末。

其他分类应有真实可读的展示内容，但不调用系统功能。

## 8. 原型控制器

提供默认折叠、视觉权重较低的原型控制器。展开后可：

- 打开日期详情。
- 打开日程编辑。
- 打开任务编辑。
- 打开便签编辑。
- 打开设置。
- 切换背景模式。
- 重置演示状态。

控制器用于设计验收，不应遮挡主要内容；可放置在视口底部边缘。主界面中的真实入口必须同样可打开相应状态。

## 9. 响应式规则

### 9.1 1920×1080

作为最佳展示尺寸：

- 日历与右栏保持约 1.6:0.75 的视觉比例。
- 日历单元格可完整显示 2–3 条日程。
- 顶部和卡片间距保持舒适。

### 9.2 1366×768

进入紧凑模式：

- 缩小页面边距、卡片间距、标题字号和按钮高度。
- 日历单元格最多展示 1–2 条日程。
- 右栏摘要减少次要文字，但三个核心模块仍同时可见。
- 弹窗最大高度限制于视口，Body 内滚动。

### 9.3 2560×1440 及以上

- 内容可设置合理最大宽度并居中，避免无限拉伸。
- 增加外部留白和日历单元格高度，不盲目增加信息数量。
- 保持平衡型信息密度。

任何尺寸下都不得出现页面级水平或垂直滚动条。

## 10. 交互与状态反馈

原型实现以下展示级交互：

- 打开、关闭和在相关弹窗间切换。
- 浅色渐变与桌面融合背景切换。
- 任务完成视觉状态切换。
- 设置分类切换。
- 四象限选中状态切换。
- 日程颜色和便签颜色选中状态切换。
- 设置项开关和范围控件的视觉反馈。
- 上一月、今天、下一月的展示级标题反馈。
- 原型状态重置。

不实现数据持久化；刷新页面恢复初始演示状态。

## 11. 无障碍与动效

- 使用语义化 `header`、`main`、`section`、`button`、`dialog` 和表单标签。
- 图标按钮提供可读的 `aria-label`。
- 所有可操作元素具备 hover、active、focus-visible 和 disabled 状态。
- 文本对比度以 WCAG 2.2 AA 为最低目标。
- 对话框使用合适的 `role`、`aria-modal` 和标题关联。
- 键盘可访问主要按钮、控件和弹窗操作。
- 尊重 `prefers-reduced-motion`；正常动效限制在 150–200ms。
- 状态不能仅通过颜色表达。

## 12. 技术交付

交付一个独立 HTML 文件，内含：

- 语义化 HTML。
- 原生 CSS，包括设计 Token 和响应式媒体查询。
- 少量原生 JavaScript，用于展示级交互。
- 内联 SVG 图标或纯 CSS 图标仅限该独立设计原型；后续迁移到产品代码时必须替换为 `lucide-react` 图标组件。

原型不依赖网络资源，以确保文件可离线直接打开。若采用内嵌 SVG 图标，应保持统一的 Lucide 风格笔画，且不得将这些 SVG 复制到正式 React 业务组件中。

建议交付路径：

`docs/prototypes/nowly-final-uiux.html`

## 13. 验收标准

1. 单文件可在现代桌面浏览器中直接打开。
2. 主界面明显体现 Good / Keenthemes 视觉语言。
3. 不出现后台侧栏、复杂导航或无关装饰。
4. 日历、四象限和便签在主界面同时可见。
5. 页面级无水平和垂直滚动条。
6. 浅色渐变和桌面融合模式均可查看。
7. 五类弹窗均可从主界面或原型控制器打开。
8. 主要按钮、任务状态、设置分类和选项具有展示级反馈。
9. 1366×768、1920×1080、2560×1440 下布局可用且无溢出。
10. 弹窗在小视口内不超出屏幕，内容区可内部滚动。
11. 使用真实中文内容，不出现无意义占位文案、设计注释或开发说明。
12. 键盘焦点可见，`Esc` 可关闭弹窗，并尊重减少动效设置。
13. 刷新页面可恢复初始演示状态，不需要持久化。
