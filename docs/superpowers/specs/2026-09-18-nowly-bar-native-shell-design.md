# Nowly Bar 原生连续外壳设计

**日期：** 2026-09-18
**状态：** 已批准
**范围：** Windows `quick-panel-handle` 原生窗口、收起态 Nowly Bar 外壳、原生区域与验收

## 1. 问题

Nowly Bar 当前由一个透明、置顶的 Tauri 顶层窗口承载。AI 面板需要 `408×440px`，收起态状态轨道只显示 `288×40px`，因此现有实现让原生窗口固定保留 408px 宽度，并在收起态留下两侧透明区域。状态胶囊与 Logo 之间还保留 8px 透明间隙。

这带来三个不同层面的问题：

1. 透明像素会显示后方窗口。后方是 Windows 标题栏时，标题栏颜色和系统按钮可能看起来属于 Nowly Bar。
2. 视觉透明不等于原生命中透明。矩形窗口区域中的透明间隙仍可能拦截后方应用的鼠标输入。
3. Tao 的 Windows 顶层无装饰窗口仍保留 `WS_CAPTION`、`WS_SYSMENU`、`WS_MINIMIZEBOX` 和 `WS_MAXIMIZEBOX`，再通过 `WM_NCCALCSIZE` 模拟无边框。窗口尺寸、区域、DPI 或 DWM 框架重算时存在系统装饰重新绘制的风险。

本轮不把问题视为 CSS 背景缺陷，而是修正原生窗口类型、可见表面和命中区域之间的不一致。

## 2. 目标

- 收起态呈现为一个连续的 `288×40px` 白色圆角外壳。
- 状态区和 Logo 区保持独立操作语义，但二者之间不再存在透明缝隙。
- 两个操作区之间使用 `1px #F6F1E9` 轻分隔线，上下各留 9px。
- 状态详情保持 `288×288px`，AI 对话保持 `408×440px`。
- Logo → AI 输入 → AI 对话的 Fluid Morph 行为保持不变。
- Windows HWND 不再具有标题栏、系统菜单、最小化、最大化或可调整边框样式。
- 原生窗口区域与当前可见圆角外壳一致，区域外真正点击穿透。
- 原生初始化失败时隐藏 Nowly Bar，但不得阻止主窗口启动。

## 3. 非目标

- 不重做状态内容、提醒业务逻辑或 AI 助手能力。
- 不更改现有面板文案、权限边界、确认后执行规则。
- 不拆成多个原生窗口。
- 不引入 Acrylic、Mica、玻璃模糊或透明背景条。
- 不修改主窗口的 Windows 样式。
- 不重构无关的 `quick_panel.rs` 状态机。

## 4. 视觉与交互

### 4.1 收起态

收起态由一个连续的 `288×40px` 白色表面承载：

- 外框：`1px solid #EAEAEA`
- 圆角：`20px`
- 阴影：无
- 左侧状态区：保持现有状态图标、标题、摘要和拖动行为
- 右侧 Logo 区：48px 宽，保留独立按钮和无障碍名称
- 分隔：Logo 区左边缘绘制 `1px #F6F1E9` 轻分隔线，线高 22px，垂直居中

分隔线只表达操作区边界，底层仍是连续白色，不允许后方内容穿透。

### 4.2 状态详情

状态外壳从 `288×40px / 20px` 连续形变到 `288×288px / 15.2px`。Logo 操作区淡出，状态内容按最终尺寸定位并被外壳逐渐露出。状态内容、移动说明和关闭行为保持现状。

### 4.3 AI 输入与对话

点击 Logo 后，AI 外壳仍从 Logo 所在位置向左扩展到输入态。提交后原生窗口先扩展到 `408×440px`，AI 外壳再按既有 Fluid Morph 展开。关闭时先完成 WebView 内形变，再缩小原生区域。

状态连续外壳作为一个整体交叉淡变，不允许再次出现独立白色圆形 Logo 与状态胶囊之间的透明裂缝。

## 5. Windows 原生窗口

### 5.1 HWND 样式

仅处理窗口标签 `quick-panel-handle`。原生初始化时读取当前 `GWL_STYLE`，规范化为：

- 添加 `WS_POPUP`
- 移除 `WS_CAPTION`
- 移除 `WS_THICKFRAME`
- 移除 `WS_SYSMENU`
- 移除 `WS_MINIMIZEBOX`
- 移除 `WS_MAXIMIZEBOX`

保留与显示、子窗口裁剪及现有运行逻辑有关的其它样式位。修改后调用 `SetWindowLongPtrW`，并通过：

```text
SetWindowPos(
  SWP_FRAMECHANGED |
  SWP_NOMOVE |
  SWP_NOSIZE |
  SWP_NOZORDER |
  SWP_NOACTIVATE
)
```

立即刷新窗口框架。

样式规范化必须是幂等操作。初始化、DPI/显示器重新协调和显示前可以安全重复调用；样式已经正确时不得重复触发框架重建。

### 5.2 焦点

不得永久添加 `WS_EX_NOACTIVATE`。状态详情中的操作和 AI 输入框都需要正常获得键盘焦点。启动配置的 `focus: false` 只表示窗口初次显示时不抢焦点。

### 5.3 原生区域

Windows 区域使用圆角矩形，而不是当前的普通矩形：

| 状态 | 区域 | 逻辑圆角 |
|---|---:|---:|
| 收起 | 居中 `288×40px` | 20px |
| 状态详情 | 居中 `288×288px` | 15.2px |
| AI 对话 | `408×440px` | 15.2px |

所有尺寸和圆角按目标显示器 scale factor 转换为物理像素。区域外不属于 HWND；圆角以外和 408px 宿主两侧留白都必须点击穿透。

收起态不再存在内部透明间隙，因此不需要从区域中扣除状态区与 Logo 之间的空洞。

## 6. 代码边界

- `src-tauri/src/quick_panel.rs`
  - 保存纯样式规范化函数。
  - 保存纯区域几何计算。
  - 在 Windows 初始化和位置协调中应用 HWND 样式及圆角区域。
  - 原生失败时隐藏 Bar 并返回可诊断错误。
- `src-tauri/tauri.conf.json`
  - 明确将 Bar 标记为不可最小化、不可最大化、不可调整尺寸。
  - 保持透明、无阴影、置顶、跳过任务栏和初始隐藏。
- `src/app/layout/StatusIsland.tsx`
  - 将收起态状态表面与 Logo 放入同一个连续外壳。
  - 保持状态与 AI 为独立面板和独立动画状态。
- `src/app/styles.css`
  - 让连续外壳拥有唯一背景、边框、圆角和裁剪。
  - Logo 区只绘制轻分隔，不再拥有独立圆形白底和边框。
- `tests/nowly-bar-assistant.spec.ts`
  - 验证连续外壳、轻分隔和 AI 形变。
- `tests/screen-status-island.spec.ts`
  - 验证状态详情从同一个连续外壳展开。

不新增第二套状态机，不把原生样式操作扩散到主窗口。

## 7. 错误处理

以下操作失败时，初始化必须隐藏 `quick-panel-handle` 并返回包含上下文的错误：

- 读取或写入 HWND 样式失败
- `SWP_FRAMECHANGED` 失败
- 创建或应用圆角区域失败
- WebView2 透明底色配置失败
- 初次尺寸或位置协调失败

主应用继续启动，并通过现有错误输出记录原因。不得降级显示带系统标题栏或不正确命中区域的 Bar。

运行期间的非初始化协调失败继续记录错误；现有可见 Bar 不应被无条件销毁。

## 8. 测试与验收

### 8.1 Rust 自动测试

- 输入包含所有普通窗口装饰位的样式，规范化结果必须删除五个危险位并添加 `WS_POPUP`。
- 已规范化样式再次规范化，结果不变。
- 不相关样式位必须保留。
- 100%、125%、150%、175%、200% DPI 下验证三个状态的物理尺寸、位置和圆角。
- 收起态和状态详情区域保持居中；AI 区域占满 408px 宿主。

### 8.2 浏览器测试

- `.status-rail__status-presence` 是唯一收起态白色外壳。
- 状态内容和 Logo 位于该外壳内部。
- Logo 不再拥有独立外边框或独立白色圆形表面。
- Logo 左侧轻分隔为 `1px #F6F1E9`，上下留白正确。
- 收起态外壳为 `288×40px / 20px`。
- 状态详情为 `288×288px / 15.2px`。
- AI 输入与对话尺寸、关闭路径、反向操作和 reduced-motion 行为不回归。

### 8.3 真实 Windows 验收

在真实 Tauri 进程中读取 `GWL_STYLE` 并确认：

```text
WS_CAPTION       == 0
WS_THICKFRAME    == 0
WS_SYSMENU       == 0
WS_MINIMIZEBOX   == 0
WS_MAXIMIZEBOX   == 0
WS_POPUP         != 0
```

随后验证：

- 后方窗口使用可见 Windows 标题栏和三个系统按钮。
- Bar 内没有背景或系统按钮穿透。
- Bar 圆角外点击落到后方程序。
- 状态详情和 AI 输入仍可获得键盘焦点。
- 连续打开、关闭、反向操作不少于 20 次。
- 拖动、显示器切换、DPI 切换、睡眠恢复后样式和区域保持正确。
