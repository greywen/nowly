## 1. 判定与证据规则

每项最终必须记录：

- 精确提交、依赖锁定版本、Windows 构建号、WebView2 版本、显示器配置及执行日期。
- 测试输入、执行步骤、实际结果、独立期望结果、PASS/FAIL/UNSUPPORTED 判定。
- 自动化日志、原生窗口属性、输出文件/像素比较、必要录屏或人工操作记录的证据路径。
- 不能用“库 README 写支持”“前端测试通过”“接口返回成功”“模型说图片看起来正常”替代输出校验。
- UNSUPPORTED 必须注明系统/应用限制与用户可见反馈，不等于 PASS；批准范围内的常规路径不能以此逃避验收。

状态只取 NOT_RUN、RUNNING、PASS、FAIL、UNSUPPORTED；未执行不得改成 PASS。产品规格确认、技术验证通过、实现完成和发布验收是四种不同结论。

### 1.1 三层验证

| 层级 | 能证明 | 不能证明 |
|---|---|---|
| 纯模型/单元测试 | 坐标换算、状态迁移、裁切、历史、拼接判定、容量/权限边界 | 真实 DWM、系统剪贴板或目标应用行为 |
| WebView/浏览器交互测试 | 工具栏、键盘、IME 事件处理、属性控件、布局与样式 | 原生覆盖层、混合 DPI、全局按键、真实桌面抓图 |
| 真实 Windows 集成/人工验收 | HWND、系统剪贴板、捕获排除、输入注入、HDR、系统对话框和真实应用拼接 | 未覆盖设备/应用也必然兼容 |

真实 IME、焦点、系统对话框和跨应用粘贴必须有第三层证据，不能只有模拟事件。

### 1.2 代表性环境

- Windows 11 的实际验收构建；如当前产品继续支持 Windows 10，同时测试 Windows 10 22H2。记录具体构建，不借此改动 Nowly 整体支持范围。
- 单屏 1080p、单屏 4K、双屏混合 DPI。
- 缩放 100%、125%、150%、200%；主副屏左右互换、负 X/负 Y、上下排列、竖屏和存在桌面空隙的排列。
- SDR 为精确像素基准；另测 HDR 开启、混合 HDR/SDR。若没有设备，相关项目保持 NOT_RUN。
- 真实应用：Edge/Chrome 常规网页、微信聊天内容、普通 Win32 文本滚动控件、一个虚拟列表/嵌套滚动示例。
- 标准权限应用；另测目标为管理员权限、目标最小化/遮挡/失焦、远程桌面连接中断等边界。

使用专用非敏感测试内容；不得把个人聊天、合同、账户信息作为证据样本。真实应用的滚动、复制、文件覆盖操作应在后续明确授权的测试环境内进行。

## 3. 逐项验证

### V00：依赖与平台可行性

**2026-09-25 第二次实际结果（自有 GDI 后端）**

- 基线提交：`b1e114dd81c7afc1bfb3da9cec6c6bc0f5e75350` 加当前未提交实现；Windows `10.0.26200.8655`，WebView2 `153.0.4234.48`，Rust/Cargo `1.94.1`。单屏 `2240×1400`，150% 缩放。
- **放弃第三方抓屏库，改为自实现 GDI 后端**（`src-tauri/src/screen_capture/gdi.rs`）。`xcap` 对每个显示器按设备名建 DC，在本机返回 `0x80070006`；本实现改用 `GetDC(None)` 取整个虚拟屏幕 DC，再按显示器物理矩形 `BitBlt`，不需要逐适配器设备。
- **稳定性已达标：** 连续 20 轮重复捕获 20/20 成功，无一轮失败，无全一色帧。这是对 `xcap` WGC「首次成功、重复返回 `0x80070057`」的直接对照。证据：`screen_capture::gdi::tests::gdi_captures_every_display_repeatedly`。
- **发现并修正一个隐蔽的正确性缺陷：** 首次探针报 `1493×933`、scale 1.0，看似成功，实际是 DPI 虚拟化后被拉伸的副本（2240/1.5 = 1493.3）。`EnumDisplaySettingsW` 不受虚拟化影响，作为独立真值报 `2240×1400`；设置 per-monitor-v2 后坐标改为 `2240×1400`，确认虚拟化存在。证据：`reports_whether_the_process_sees_physical_pixels`。
- 因此后端增加 `require_physical_pixels` 守卫：进程不是 per-monitor DPI aware 时返回 `NotDpiAware` 而拒绝捕获，不静默返回缩放像素。生产路径由 Tao 在 `EventLoop::new` 调用 `become_dpi_aware()` 设为 per-monitor-v2（`tao-0.35.3/src/platform_impl/windows/event_loop.rs:190`），符合要求；裸 `cargo test` 二进制不带清单，故探针必须自行设置。守卫的拒绝行为由 `refuses_to_capture_without_per_monitor_awareness` 覆盖（需在干净进程单跑）。
- **性能：** release 构建下 3.1MP 单屏捕获 ~30–60ms；debug 为 ~420ms。按面积粗估 4K 约 150ms，在 V12 的 1s 预算内。这是单项捕获计时，不等于 V12 的点击到覆盖层端到端指标。
- **依赖简化：** 删除 `xcap` 及其 `wgc` 特性，Cargo.lock 增量从 +974 行降至 +165 行。仅新增 `windows` crate 的 `Win32_UI_HiDpi` 特性（用于 DPI 守卫与 `GetDpiForMonitor`）。抓屏不再引入第三方库，也不再需要隔离 helper 进程来绕开外部库的 WGC 静态初始化 `expect`。
- 保留 `image = 0.25.10`（MIT OR Apache-2.0，仅 `png`）与 `arboard = 3.6.1`（MIT OR Apache-2.0，`image-data`）。`image` 改为无条件依赖：`windows` crate 本身已无条件，CI 也只有 windows-latest，原来的 `cfg(windows)` 分区并未带来真实跨平台能力。
- 拒绝 `react-screenshots`、`snow-stitch-images` 的结论不变（理由见下方首次记录）。
- **已知边界：** GDI 无法读取 DRM 保护表面和部分硬件覆盖层，属 V09；必须作为明确限制告知用户，不得以黑帧冒充成功。`CAPTUREBLT` 已用于包含分层窗口。本轮为单屏单 DPI；混合 DPI、负坐标、旋转、HDR 仍归 V02/V09，保持 `NOT_RUN`。

**判定：PASS。** 依赖版本、许可、构建兼容已确认；抓屏改为自有 GDI 后端后重复稳定性达标，失败路径不再依赖进程内 `catch_unwind` 隔离外部库的 FFI 回调 abort。V01、V06、V09 仍分别保持 `NOT_RUN`。

**2026-09-25 首次实际结果（第三方库候选，已被上述结果取代）**

- 基线提交：`b1e114dd81c7afc1bfb3da9cec6c6bc0f5e75350` 加当前未提交实现；Windows `10.0.26200.8655`，WebView2 `153.0.4234.48`，Rust/Cargo `1.94.1`。
- 条件保留 `xcap = 0.9.8`（Apache-2.0）及 `wgc` 作为 Windows dev-dependency 和隔离 helper 候选；`cargo tree --edges normal` 已确认它不进入生产依赖图。发布源码确认监视器接口返回有符号物理原点、物理像素宽高与 `RgbaImage`；项目内最小测试构建通过。真实内存抓屏曾在约 `0.38s` 成功，但重复执行返回 `0x80070057`，未达到稳定性门槛。其 WGC 回调线程还存在静态设备初始化 `expect`，进程内 `catch_unwind` 不能保证隔离跨 FFI 回调的 abort。上游 docs.rs 对 0.9.8 构建失败，因此不把在线文档或单次成功当作通过证据。
- 采纳 `image = 0.25.10`（MIT OR Apache-2.0），关闭默认格式，仅启用 `png`；与 xcap、arboard 共用同一解析版本。
- 采纳 `arboard = 3.6.1`（MIT OR Apache-2.0，MSRV 1.71），关闭默认特性并启用 `image-data`。发布源码确认 Windows 同时写入 PNG 注册格式与 `CF_DIBV5`；真实微信/画图/Word 粘贴属于 V06，尚未据此宣称通过。
- 拒绝 `react-screenshots`：无法覆盖本规格的物理像素、多窗口、版本化对象和分块长图边界，引入后仍需重写核心模型。
- 拒绝 `snow-stitch-images`：本规格要求可诊断的拒绝原因、已确认前缀和不猜接缝，采用可测试的自有 Stitcher；后续 V08 以独立真值标定算法。
- 已实测 xcap 默认 GDI 在主屏 `1920×1080` 的 `BitBlt` 返回 `0x80070006`；`windows-capture 2.0.1` 的同步 DXGI 在当前混合图形环境返回 `OutputNotFound`。两条路径均已从产品实现移除。
- 下一步将抓屏放入独立 helper 进程，以长度前缀二进制协议回传元数据和 RGBA；helper 崩溃、超时或返回异常时主进程恢复 Bar 并报告启动失败。完成该隔离与重复稳定性测试前不启用 `start_screen_capture`。

**判定：FAIL（已被上方第二次结果取代）。** 依赖版本、许可和构建兼容性已确认，但进程内抓屏候选未满足稳定失败隔离要求。

**方法**

1. 分别评估抓屏、编辑器、拼接器、剪贴板和 PNG 编码候选，记录精确版本/提交与实际维护来源。
2. 检查各文件/子目录的许可证、NOTICE、依赖树；不能把仓库某一子目录的许可推广到整个项目。
3. 确认 Nowly 当前 React、Rust、Tauri、`windows`/WebView2 版本是否兼容；验证是否引入 Electron、巨型运行时或未批准网络服务。
4. 若考虑 `react-screenshots`，验证其交互/样式可替换程度、React 版本、对象编辑/撤销及实际像素导出；不以静态工具列表代替测试。
5. 若考虑 `snow-stitch-images`，核查具体提交的 Rust 工具链、是否已发布、公开 API 与许可证范围；它目前只是前轮调研候选。
6. 对比普通截图与滚动捕获后端，确认窗口排除、色彩格式、光标、权限/失败返回等差异。

**PASS**

- 有锁定依赖、SBOM/许可记录和真实最小构建结果；没有未经说明的整套截图应用代码引入。
- 每个候选标记“采纳/拒绝及原因”，设计边界不依赖未证明能力。
- 不要求在本设计阶段安装依赖；未开展验证时仍是 NOT_RUN。

### V01：干净抓屏与捕获排除

**输入与独立判据**

- 专用桌面测试图：唯一色块、坐标格线及不同区域编号。
- 给 Bar、覆盖层、放大镜、控制条、鼠标光标各放一个易识别的测试标记。
- 期望输出来自原始测试图和已知裁切坐标，不来自待测截图程序生成的“期望图”。

**步骤**

1. 冷启动与热启动各重复进入截图；涵盖 Bar 靠边、两种提醒模式和上一次面板形变刚结束的时序。
2. 检查隐藏→DWM 更新→抓底图→显示 overlay 的真实顺序，注入慢帧、延迟显示/隐藏回调。
3. 逐项验证排除控制窗、鼠标穿透与无激活，不能用任意一项成功代替另外两项。
4. 滚动期间将控制条放在选区内/外，检查所有帧，而非仅最终静态图。
5. 测试排除 API 不可用或返回失败的环境；不能默默改为把工具栏截入图片。
6. 每屏记录本次 hide-generation 与帧获取时间/版本；注入某一屏迟到、复用旧帧或超时，验证全有或全无及 STARTING 的 5 秒故障上限，不把少屏结果当成功。

**PASS**

- 选区内输出无任何自有辅助标记或光标；Nowly 主窗口仍能作为普通内容被截取。
- 正常 SDR 基准的底图裁切与独立期望像素一致。
- 抓取失败有错误分类且恢复 Bar；不把“空缓冲/未初始化缓冲”返回成功。

微软说明 `WDA_EXCLUDEFROMCAPTURE` 是特定公共捕获 API 的窗口排除机制，不是安全/DRM 保证，且有版本条件；应验证所选后端而非只检查 API 调用成功。[S1]

### V02：多屏、DPI、坐标和取色

**数据集**

- 为每屏生成带物理像素坐标的无缩放测试图：四角、1px 条纹、8 色大色块、屏幕边界编号。
- 覆盖单屏每档 DPI、100%+150%、125%+200%、负坐标、上下排列、旋转和非矩形桌面空隙。
- 基准 SDR 测试关闭 HDR/夜间模式，并记录色彩配置；测试目标是捕获数据的一致性，不是显示器物理色度测量。

**步骤与 PASS**

- 取色坐标恰为被选物理像素，HEX 与导出的同底图该像素完全一致；主副屏不因全局 DPI 换算错位。
- 框选 1×1、反向矩形、整屏、跨屏、贴边选区；期望输出宽高完全相等，四条裁切边无多/少一像素。
- 已知同一显示器像素不因跨屏选区而重新缩放；空隙按规格填白，但不能从空隙复制伪色值。
- Ctrl+C 复制后剪贴板只有 7 字符 HEX，会话和底图不变；无有效像素时旧剪贴板不变。
- 在屏幕边缘移动，放大镜不越界、不覆盖被测像素、不从放大镜自身采样。
- 跨屏拖动期间指针离开单个 WebView 仍不中断；不能只用网页 viewport 模拟跨屏。

证据应包含显示器物理矩形/scale 表、选区整数坐标、文件尺寸与逐像素差异计数，而不仅是一张肉眼截图。

### V03：Bar 隐藏、并发与恢复

**矩阵**

- persistent / notification 模式。
- 启动、取消、色值复制、图片复制成功/失败、保存成功/取消/失败。
- 新提醒到达、旧提醒自动变化、后台 AI 请求完成、设置变更和 Bar 定位线程回调。
- 捕获失败、部分 overlay 创建失败、前端失联、应用退出、锁屏、显示器热插拔。
- 快速连续点击、启动立即取消、旧导出结果在新会话开始后才返回。

**PASS**

- 每次最多一个会话；原生 HWND 数量、可见性、topmost、region、焦点与预期一致。
- Bar 的显示器/逻辑偏移正确恢复；主屏降级不覆写原有显示器偏好。
- 截图期间不被定位线程或新提醒重新显示；取消不确认提醒、不清空 AI 输入、不回滚后台业务更新。
- 不直接依赖仅允许 notification 模式隐藏的业务接口；截图抑制与业务可见性分开。
- 所有退出路径都移除 overlay、临时按键处理与滚轮任务；透明区域实际能点击到底下测试应用。
- 迟到结果被会话/版本检查拒绝，不能关闭新会话或写入过时图片。
- 保存对话框正确 owner/焦点恢复，普通 Alt+Tab 不抢焦点，并且能从唯一的“Nowly 截图”任务切换入口返回原会话；辅助屏不产生多个任务项。滚动 Alt+Tab 立即暂停自动输入。
- 原前台窗口已销毁、句柄复用或用户已切换到其他应用时，不激活错误窗口；原窗口恢复最多尝试一次。
- 用独立前台窗口事件时间线验证“原目标”在 Bar 激活前记录；目标既覆盖外部应用，也覆盖用户本来激活的 Nowly 主窗口，不能一律记录成 Bar 或一律排除主窗口。
- 检查 Alt+Tab、任务栏悬停、Peek 和截图挂起后的缩略图；只显示静态占位，无冻结桌面/未打码图像或旧敏感帧残留。

### V04：选区、键盘、IME 与焦点

以设计文档 §7 为完整键盘状态表，逐个组合验证，而不是只测 Ctrl+C 的成功路径。

**必须覆盖**

- 框选前 Ctrl+C→HEX；框选完成后 Ctrl+C→图片；文字框 Ctrl+C→文字；拖选/笔画中 Ctrl+C 不导出半成品。
- 真正的中文 IME 组合输入与候选框：Enter/Esc 不提前完成截图，Ctrl+S 不提交未完成候选内容。
- Esc 分层：对话框、IME、文本草稿、弹层、绘制、所选对象、滚动、整个会话。
- 空文本不生成对象；已有文字 Esc 恢复编辑前内容；文本 Enter 换行，Ctrl+Enter 提交。
- Ctrl+Z/Y 在文本与标注间正确分派，Delete/Backspace 不触发网页后退。
- SCROLL_PREPARE/SCROLLING/SCROLL_PAUSED/SCROLL_REVIEW 分别测试 Ctrl+C/S/Enter 与 Esc，覆盖目标应用、Nowly 控制条、文本与画布焦点；未确认结果不能导出，Esc 不能恢复滚轮输入。
- 鼠标反向框选、1px 框选、移动、八向调整，键盘移动与调整最小范围。
- 跨屏指针捕获丢失、pointercancel、画笔/框选/变换中 Alt+Tab，仅撤销当前未提交事务，不自动补一次松手提交。
- 全屏和极小选区下工具栏与完成/取消仍可触达；鼠标右键不穿透底层应用。
- 工具按钮、输入框、画布各有确定的焦点，Enter 不同时触发按钮和“完成”。
- Shift+Tab、可访问名称、选中状态和必要提示；live region 不按每帧朗读鼠标坐标。
- 仅键盘用 `[`/`]` 循环选择旧对象，听到类型/序号，随后移动、修改属性、删除或 Enter 编辑文字；同样按键在文本/IME 内不被截获。

**PASS**

全部状态动作只有一个明确处理者；本地编辑操作不产生剪贴板/文件副作用，焦点切换不丢失草稿。

### V05：标注、马赛克和输出一致性

**独立样本**

- 无标注基准图、边界线/箭头、自由笔曲线、中文/英文/多行文字、重叠对象。
- 隐私测试使用专门生成的虚构数字和文案，不使用真实个人信息。
- 马赛克期望按已定义网格和块值计算，独立于生产渲染实现。

**步骤与 PASS**

- 六种绘制工具均可按规格创建、选择、修改、删除；工具参数在不同预览倍率下对应同样输出像素。
- 每次拖动/笔画只有一次 undo；undo→redo 恢复同一模型；新操作清空 redo。
- 取消草稿没有隐藏对象；撤销到零标注才解锁普通选区和滚动入口。
- 撤销到零→改变选区→redo 不得恢复旧对象；中止选区调整则保留 redo；进入长截图后取消恢复原历史，确认采用长图后历史清空。
- 原始底图不被直接破坏；普通标注叠加顺序和最终马赛克遮挡顺序一致。
- 按规格的 sRGB 通道算术均值/四舍五入算法，独立计算部分边缘块、多马赛克交叠及不同块大小；PNG/剪贴板结果一致。移除 UI 图层后仍保持遮挡；PNG 不含可恢复的原始图层/附加未遮挡图片。
- 预览和导出使用同一坐标/字体/换行规则。选区和马赛克网格要求像素位置精确；字体边缘抗锯齿差异必须有单独标定容差，不能掩盖字体替换、换行或对象错位。
- 标注在长图分块边界上不断笔、不重复、不漏绘；导出不含控制点、辅助轮廓和工具栏阴影。

### V06：剪贴板与 PNG 保存

**剪贴板**

1. 使用独立 Windows clipboard 检查器枚举实际格式，读回像素与尺寸。
2. 将 HEX 粘贴到纯文本编辑器，图片分别粘贴到微信、画图、Word。
3. 检查粘贴的是图像而不是文件路径/字符串；像素尺寸、方向、颜色与输出图一致。
4. 覆盖剪贴板被其他进程占用、写入部分失败、大图缓冲分配失败、重复完成操作。

**保存**

1. 中文/空格路径、长路径在系统实际允许范围内、同名文件、取消覆盖、无权限、磁盘满、目录被移除。
2. 保存中取消系统对话框，验证完整回到原图/选区/标注/工具状态。
3. 使用独立 PNG 解码器验证尺寸、像素、色彩信息与无多余来源元数据。
4. 替换一个已记录哈希的测试 PNG，注入写入失败，验证旧文件不受损；只对明确的测试文件执行。
5. 模拟编码失败和关闭应用，检查本次明确拥有的临时文件清理，不扫描删除整个临时目录。
6. 分别在编码中、准备提交前和实际提交中发出取消；前两者无输出副作用并返回编辑，提交中以真实结果为准，不把成功写入报告为“已取消”。
7. 在保存对话框返回后、临时文件创建前及提交前注入目录/目标身份变化、junction/symlink/reparse 替换；覆盖本地 NTFS、实际支持的可移动/网络卷。不能满足安全提交时拒绝覆盖并保留旧文件，不能错误宣称所有文件系统均具原子保证。

**PASS**

- 仅真实写入成功才退出；失败/取消保留编辑器，可重试。
- 保存不隐式改剪贴板；无文件选择时不生成截图文件。
- 已成功写出的用户文件不随会话清理删除。

Tauri Clipboard 的默认权限不自动开放所有操作；图片与文本写入必须按实际需要显式授权并验证真实输出格式。[S4]

### V07：滚动目标、输入和控制窗

**场景**

- 同一窗口两个独立滚动面板、窗口内嵌控件、浏览器页面和微信聊天记录。
- 选区中心不是目标面板时重新指定滚动点。
- 目标普通权限/管理员权限、前台变更、窗口移动/缩放/关闭、被无关窗口覆盖、句柄被复用。
- 选区贴边/全屏，控制条只能放在选区内的情况。

**PASS**

- 准备阶段选择目标点不会点击到底层链接/按钮；开始不通过虚构内容点击抢焦点。
- 手动模式输入正常到达底层应用；Nowly 不截获普通 Ctrl+C/S/Enter。
- 自动模式仅操作已绑定目标；每次输入前验证，不持续向新前台窗口发送消息。
- 临时 Esc 一次停止滚动进入结果确认；停止后无遗留全局按键拦截。
- 暂停时 Esc 同样进入结果确认；结果确认 Esc 返回原普通截图，不恢复自动输入；所有重新采集只来自明确的开始/继续动作。
- UIPI/权限失败可切回手动，并显示原因；不自动以管理员重启 Nowly。
- 控制条“可点击”“不抢目标焦点”“不进入图片”分别通过实测。
- 切换应用/失效目标后，不接受新帧或新滚轮输入；停止响应目标为用户动作起 100ms 内停止排队新输入。操作系统已投递输入不承诺撤回，必须记录是否仍有残余滚动。

Windows `SendInput` 受完整性等级限制，且失败返回不能可靠单独归因为 UIPI；验证不能只记录“返回 0”而猜测唯一原因。[S2]

### V08：长图拼接、完整性与容量

#### 可重复的独立真值

先建立可控滚动样本，每个内容行含唯一编号/条码及已知布局，同时提供独立生成的整张原图。不能用待测拼接器自己产生期望长图。

至少覆盖：

- 纯文本、表格、交替条纹、长段单色、外观重复但编号不同的列表行。
- 固定头、固定尾、固定侧栏及滚动条。
- 懒加载图片、动态时间/光标、小动画与大面积视频。
- 嵌套滚动、虚拟列表、滚动条跳跃、快滚、向上回看再向下、到底不动。
- 不同帧重叠比例、噪声、掉帧、采样不稳定与目标场景突然改变。

#### PASS 门槛

- 对可控静态基准，所有唯一行编号恰好一次、顺序正确；无漏行、重复行、错序、横向偏移，输出有效范围与独立真值一致。
- 固定头尾只保留一次，不裁掉首条/末条内容；侧栏不能干扰长图位移匹配。
- 无重叠、低纹理、重复纹理冲突和场景切换必须拒绝或暂停，不能用上一帧位移猜接缝后报完整成功。
- 暂停继续必须重新建立真实重叠；向上回看不重复追加。
- 单纯无变化不能被当作完整到底证明；正确显示未检测到新增内容/待用户确认。
- 丢弃未确认帧后，导出的“已截部分”与已确认前缀完全一致，不偷偷包含被拒绝区域。
- 采集中/结果确认的预览也只能显示已确认前缀；拒绝原因及接缝标尺单独呈现，有可访问名称且不进入 PNG/剪贴板。
- 开始长截图时重新抓第一帧；取消返回原普通截图底图，不把两个不同时刻的底图混合。
- 对真实应用记录其实际支持范围；遇到视频或持续变动内容拒绝自动拼接可为预期结果，但不能把这种保护行为称为该内容已支持正确长截。

#### 容量与队列

- 在总像素 64,000,000、单边 65,535 及 512 MiB 会话显式分配预算上下边界分别测试。
- 单独覆盖框选前的成本：多块 4K/8K、源像素合计超过 64MP、显示器之间巨大空隙、HDR staging 与预览多副本。源像素不等于输出像素；预算可容纳时允许冻结来源，无法容纳时在隐藏/大分配前拒绝，不漏屏、不用整块空隙画布浪费内存。
- 大于像素/尺寸上限的请求在昂贵分配之前拒绝；尺寸乘法、行跨度、负坐标等全部做溢出/越界检查。
- 边界以下不等于所有操作必定成功；每次复制/合成/编码都预检峰值缓冲，失败保留可用内容且不静默缩小。
- 输出跨多个图像瓦片，浏览器可见区域之外不创建整高画布；块边界像素与完整真值一致。
- 慢拼接器、慢编码器和高速滚动下队列仍有界；丢弃候选帧不能丢失连续性判定。
- 循环采集/取消/导出后会话缓冲释放；记录 Rust 管理缓冲、WebView/GPU 内存及整体进程增量，不把其中一个数字冒充全部内存。

ShareX 官方文档明确记录固定区域、动画及悬停变化对滚动拼接的影响，可作为兼容场景参考，不是 Nowly 的通过证据。[S5]

### V09：HDR、受保护内容和特殊桌面

**步骤与 PASS**

- SDR 标准色块、HDR 开启、HDR/SDR 双屏：记录抓取格式、转换步骤和输出 sRGB 信息。
- HDR 转换后取色、预览、文件/剪贴板保持同一数据路径；不宣称 HDR 数值等于网页源 HEX。
- HDR 场景检查过曝、发灰、颜色通道交换和跨屏色域不一致；缺少 HDR 设备时不得标记 PASS。
- 合法的纯黑、纯白和透明内容可以输出；不能把黑帧启发式当作受保护内容判定。
- 对 API 明确报告的拒绝/不可用给出用户可见限制；保护机制导致的黑区域而 API 无法辨认时如实说明边界，不能宣称已可靠识别所有保护内容。
- UAC 安全桌面、锁屏、会话切换停止捕获；不自动切换桌面或提升权限。
- 远程桌面连接断开/重连、目标最小化、显示器断开，不能留下透明输入拦截窗口或旧坐标自动输入任务。

微软的屏幕捕获文档专门说明 HDR 管线与像素格式选择；普通 SDR 的成功不能外推为 HDR 通过。[S3]

**浏览器与原生分别检查**

- Bar 紧凑控件 28/16，编辑工具栏标准控件 40/18，图标统一 Solar 且服从用户选定风格。

- 读屏只宣布工具、操作结果、尺寸调整完成及错误等有用变化，不高频朗读全部鼠标坐标。
- 对实际色彩对比、Windows 高对比模式作记录；若需修订统一 Token，回到 `design.md` 确认，不能私造一套截图样式或无证据宣称 WCAG 达标。

### V11：权限、隐私、错误与清理

**负向测试**

- 非截图窗口调用抓帧、读取其他 session、导出旧版本或指定任意保存路径。
- 会话结束后继续取瓦片、重复使用令牌、猜测其他窗口 label、跨会话引用底图。
- 在隔离测试页中构造虚构像素 canary，通过 fetch、WebSocket、表单、远程图片、弹窗/导航尝试发送到受控测试端点；必须主动被截图窗口策略阻止，服务端未收到 canary。正常流程没有请求不能替代该负向测试。
- 异常尺寸、负宽高、超大坐标、非法对象属性、无效图片缓冲。
- 临时文件所有权记录缺失/变化，用户改写同名文件，进程崩溃后重启。

**PASS**

- Rust 端拒绝无效调用；不能只依赖前端隐藏按钮或窗口 capability。
- 截图窗口权限不包含业务配置/数据库写入、任意路径访问或远程页面 IPC。
- 出站限制只作用于截图窗口；本地资源/IPC 仍可用，现有 AI/主窗口的已授权网络流程不因截图专用策略被禁用。
- 无截图上传、AI 调用、附件入库、历史记录或后台持续采屏；通过受控网络记录和存储前后差异验证。
- 诊断不包含像素、窗口标题、轨迹、文本内容和保存路径；复制到系统剪贴板的外部可见边界有明确说明。
- 正常结束释放资源；临时清理只针对有确切归属且仍符合校验的文件，不宽泛递归删除。
- 故障清理不删除已保存 PNG、不擦除用户剪贴板、不覆盖用户当前提醒/AI 业务状态。

### V12：性能与完整回归

以下是拟验收目标，不是测量结果。首次基准执行时记录 CPU/GPU、RAM、分辨率及干扰负载；不能选取最快一次宣称达标。

| 场景 | 拟验收目标 | 采样要求 |
|---|---|---|
| 单屏 4K SDR 热启动截图 | 点击到可框选覆盖层 P95 ≤ 1 秒 | 30 次，计入隐藏和捕获，不仅测界面出现 |
| 同环境首次截图 | ≤ 2 秒 | 独立记录冷启动，不混入热启动样本 |
| 单屏 4K 取色/拖选/常规绘制 | 输入到界面更新 P95 ≤ 33ms；无持续超过 100ms 的 UI 冻结 | 时间戳/帧时间记录，不能只肉眼判断 |
| ≤ 8MP 图片复制 | 完成操作到实际可读剪贴板 P95 ≤ 1 秒 | 至少 20 次，系统剪贴板读回确认 |
| 自动滚动停止 | 100ms 内停止排队新的输入 | 捕获输入发送时间和停止事件；说明已投递输入边界 |
| 反复启动/取消 | 100 次无遗留窗口/钩子/后台采集任务；会话管理分配归零 | 记录 HWND、任务、分配计数，整体 RSS 单独报告 |

大图编码时间另按像素数记录，不承诺 64MP 与普通图片相同速度；UI 必须保持可取消/可恢复的静态状态反馈，编码不能阻塞窗口事件处理。
