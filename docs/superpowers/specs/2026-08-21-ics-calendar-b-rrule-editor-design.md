# Spec B｜完整 RRULE 编辑 UI

> 本 spec 是「ICS 日历彻底革新」三份子项目中的第二份，建在 Spec A 之上。
> 总览与开发进度见 `2026-08-21-ics-calendar-overview.md`。
> **前置依赖：Spec A 必须先落地**（引擎已能存储/展开/往返完整 RRULE）。

## 目标

在事件编辑弹窗里，让用户创建与编辑完整的 RFC 5545 重复规则——不止「每天/每周/每月/每年
+ 间隔 + 星期 + 结束条件」，而是覆盖 `BYDAY` 序数（每月第 3 个周二、最后一个周五）、
`BYMONTHDAY`、`BYMONTH`、`BYSETPOS`、`WKST` 等，以及为本地定时事件选择具名时区。

引擎能力由 Spec A 提供；本项目是把这些能力暴露成可用、可读的前端交互。

## 范围

本项目**做**：

- 重复规则编辑器：在现有「频率/间隔/星期/结束条件」基础上，扩展出序数星期、按月第几天、
  按月份、`BYSETPOS`、周起始日等高级选项。
- 规则的人类可读摘要：把当前配置实时翻译成一句话（如「每月的第三个周二，共 12 次」），
  降低复杂规则的理解成本。
- 本地事件的**时区选择器**：默认「设备当前时区」，可改为其他具名 IANA 时区或「浮动」。
  搜索式下拉（IANA 时区数百项，须可搜索）。
- 与 Spec A 的 RRULE 串双向绑定：编辑器状态 ↔ RRULE 串。

本项目**不做**：

- 引擎/存储改动（属 Spec A）。
- 订阅（属 Spec C）。

## 交互设计（待细化）

编辑弹窗的重复区在现有 `EventModal` 基础上扩展。高级选项在选择「自定义」重复时展开。
所有控件复用 `design.md` 规范（Good Solid 输入、青绿主色、无动效、原生 checkbox/radio、
离线 Select/DatePicker/TimePicker）。

> 本 spec 的交互细节在 Spec A 落地、引擎行为确定后再细化，届时会用可视化 companion
> 走查表单布局与规则摘要文案。此处先锁定范围与依赖。

## 时区选择器

- 触发控件采用 Good Solid 输入外观（`design.md` 8.5 / 8.7 一致）。
- 面板为可搜索列表，选项含设备当前时区（置顶、标注「当前」）、「浮动（不绑定时区）」、
  与全部 IANA 具名时区。
- 无动效，即时开合。
- 可访问性：`role`、`aria-*` 对齐现有 Select 组件。

## 测试

- 编辑器状态 ↔ RRULE 串往返：各高级选项组合生成的串与 Spec A 引擎一致。
- 规则摘要文案在中英文下的正确性。
- 时区选择器搜索、选择、键盘操作与可访问性。
- 无动效约束回归。
