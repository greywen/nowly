# 高斯模糊隐私遮挡设计

## 背景

Nowly 当前顶部导航栏提供“透明度”控制，通过调整应用内容透明度透出壁纸。用户希望将该能力改为桌面隐私遮挡：拖动控件时实时模糊整个 Nowly 页面，并在设置为壁纸后继续保持模糊状态。

## 目标

- 将现有透明度控制替换为高斯模糊控制。
- 滑块实时控制整个应用页面的模糊程度。
- 模糊范围包括顶部导航栏、工作区、模块及弹窗内容。
- 设为壁纸后不重置模糊值，继续保持当前模糊效果。
- 模糊值持久化，应用重启后恢复。
- 遵循项目设计规范：无 transition、animation 或其他动效。

## 非目标

- 不再提供原有页面透明度调节能力。
- 不新增独立的透明度滑块。
- 不对桌面壁纸层本身施加模糊。
- 不设计新的弹窗或改变顶部导航布局。

## 交互设计

顶部导航栏保留现有 Blend 图标控件及位置，弹出面板改为：

- 标题：`高斯模糊`
- 数值：显示当前模糊半径，例如 `8px`
- 滑块范围：`0–24px`
- 步长：`1px`
- 默认值：`0px`
- `0px` 表示清晰；数值越大，隐私遮挡越强。
- 拖动 `input[type="range"]` 时立即更新页面模糊，无延迟或过渡。
- 控件保留现有键盘操作、焦点样式、Esc 和点击外部关闭行为。
- 无障碍名称、`aria-valuetext` 和可见文案均使用“高斯模糊”语义。

## 技术设计

### 状态与持久化

将 `src/app/useTransparency.ts` 改为模糊状态 hook（可保留文件名以降低无关改动，或同步重命名其测试文件）：

- 存储键改为独立的 `nowly:page-blur-radius`。
- 状态类型为数字，范围限制在 `0–24`。
- 无效或缺失值回退到 `0`。
- setter 先更新 React 状态，再尽力写入 `localStorage`。
- 不读取或迁移旧透明度值，避免旧配置意外改变隐私遮挡强度。

### 页面应用范围

在 `App` 中读取模糊状态，并把它传给 `DesktopShell`。在 `.app-shell` 根容器上通过 CSS 自定义属性应用：

```css
.app-shell {
  --app-blur-radius: 0px;
  filter: blur(var(--app-blur-radius));
}
```

`DesktopShell` 的根 `.app-shell` 必须包含顶部导航、工作区及其页面内容，因此导航栏也会被模糊。模糊值在前景模式和壁纸模式之间切换时保持同一份 React 状态，不因 `enterWallpaperMode` 或 `enterForegroundMode` 重置。

实现时应检查全屏根容器的边缘表现；如浏览器渲染造成模糊边缘裁切，只允许采用不改变布局语义的静态处理，不添加缩放、位移或动效。

### 组件文案与 API

`TransparencyControl` 应改为表示模糊控制的组件或至少改内部 props / 常量命名，避免继续暴露 opacity 语义。控件接收当前 blur radius 和变更回调，并由 App 将其连接到持久化 hook。

## 错误处理

- `localStorage` 读取失败：使用默认 `0px`。
- `localStorage` 写入失败：保持当前内存中的实时模糊效果，不阻断交互。
- 超出范围或非数字值：通过 clamp 归一化到 `0–24`。
- 壁纸模式切换失败：沿用现有窗口模式错误处理，不能清除或修改模糊状态。

## 测试计划

### 单元测试

更新模糊 hook 测试，覆盖：

- 默认值为 `0`。
- 合法值写入并从 localStorage 恢复。
- 小于 `0`、大于 `24` 和非数字值被限制或回退。
- localStorage 读写异常时不抛出并保持可用。

更新控制组件测试，覆盖：

- 面板标题为“高斯模糊”。
- 数值以 `px` 显示。
- 滑块范围为 `0–24`，变更回调传递模糊半径。
- `aria-label` 与 `aria-valuetext` 使用高斯模糊语义。

### 集成 / UI 测试

- 页面根 `.app-shell` 使用当前模糊半径对应的 CSS 值。
- 顶部导航栏与工作区均位于被模糊的根容器内。
- 拖动滑块后页面即时更新，不依赖设置弹窗重新打开。
- 切换到壁纸模式后模糊值保持不变。
- 模糊值在重新加载后恢复。
- 现有透明度相关测试和窗口模式测试不应出现回归。

## 验收标准

1. 打开顶部控制并看到“高斯模糊”滑块，范围为 `0–24px`。
2. 拖动滑块时，导航栏、模块和弹窗内容同步产生对应高斯模糊。
3. 设置为壁纸后，整个页面仍保持拖动前的模糊程度。
4. 模糊值刷新或重启后仍被保留。
5. 设置为 `0px` 后页面恢复清晰。
6. 页面没有新增 transition、animation 或其他动效。
7. 既有功能测试通过。
