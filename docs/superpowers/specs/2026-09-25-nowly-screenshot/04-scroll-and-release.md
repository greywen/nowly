**当前状态：** 拼接器已完成，滚动会话本身未开始。

拼接的唯一原则是"证据不明确就不接"。§6.4 要求的每一条拒绝都是独立的理由并带诊断数字：`NoOverlap`、`Ambiguous`、`LowInformation`、`NoNewContent`、`CapacityReached`、`SizeMismatch`、`FrameTooShort`。被拒的帧一个字节都不进已确认前缀。

判定用"最优候选 + 次优候选"两个条件，而不是单看相似度：单色块、重复列表项、虚拟列表都能让某个位置得满分，光看"像"就接等于掷硬币，而掷错的结果是用户拿到一张看起来连续、实际漏行或重复的图。所以次优候选必须明显更差才接受。

**四个常量各有一项失败测试撑着**（变异测试逐个确认）：

- 去掉歧义门 → 只挂 `refuses_a_repeated_list_where_several_alignments_match_equally`。
- 去掉低信息量门 → 只挂 `refuses_a_blank_region_rather_than_trusting_a_perfect_score`。
- 把 `RUNNER_UP_EXCLUSION` 改成 0 → 只挂 `accepts_smoothly_varying_content_where_neighbouring_offsets_score_well`。渐变/照片/抗锯齿文字上，相邻一行的分数本来就几乎一样，把这种"接近平局"当歧义会把所有渐变都拒掉；次优必须是不同的对齐位置，不是冠军的邻居。
- 把 `TRIMMED_BUCKETS` 改成 0 → 只挂 `tolerates_a_scrollbar_thumb_that_moves_between_frames`。丢掉最差的那一个列桶，就吸收了滚动条滑块、窄动态侧栏、跳秒时钟，不需要先把它们识别出来。

**两处自我纠正：**

1. 第一版有 `displacement` 字段，算出来恒等于 `appended_rows`。两个名字装同一个数，会让读者以为它们互相印证，删掉了。
2. 第一版把固定页脚保留一次。但采集时无法知道哪一帧是最后一帧，保留第一帧的页脚会让它被压在图像中间——这比丢掉更糟。改为构造时就裁掉（§6.4 是"最多一次"，零次合规）。页眉不对称地保留一次是有理由的：第一帧的顶部就是结果的顶部，页脚的底部却不是结果的底部。

**阈值的诚实说明：** §6.4 要求阈值由验证集标定，且不能把第三方默认值当可靠性证明。当前阈值是针对本模块内合成验证集标定的，覆盖了规格点名的失败形态。**这不构成关于真实应用的证据**，V07–V12 仍为 NOT_RUN。

**测试数据的一处教训：** 第一版长图生成器用 `row % 251` 编行号，结果相隔 251 行的两行只有一个通道差 1——那是真正的近重复，被算法正确判为相似，而我的"无重叠"测试其实喂了一个近似匹配。修正为蓝通道带行号哈希。算法没错，是我的验证集太弱。
