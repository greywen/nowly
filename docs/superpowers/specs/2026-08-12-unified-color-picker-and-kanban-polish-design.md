# 统一颜色选择器与看板细节调整设计

日期：2026-08-12

## 1. 目标与范围

本次变更解决四项界面一致性需求：

1. 移除看板任务卡片右上角的三点菜单，但保留泳道标题栏三点菜单。
2. 泳道标题按“泳道名称 → 任务数量”显示，而不是“数量 → 泳道名称”。
3. 看板中的所有 Radio 与 Checkbox 使用项目统一的 Good Custom Solid 样式。
4. 所有现有颜色选择入口支持系统色板自定义颜色，并全局共享最近使用的 8 个自定义颜色。

颜色选择器覆盖：日历日程、便签、看板泳道、看板优先级和看板标签。协作人没有颜色字段，不新增颜色能力。此次不新增最近颜色的手动删除、命名或排序功能。

## 2. 统一颜色模型

### 2.1 存储格式

所有业务颜色统一存储为标准大写 `#RRGGBB`。前后端不再把 `blue`、`yellow`、`primary`、`danger` 等名称型值作为业务颜色格式。

主要设计系统预设色为：

- 主色青绿：`#4FC9DA`
- 成功草绿：`#B8D935`
- 信息靛蓝：`#4F55DA`
- 警告暖黄：`#E8C444`
- 危险珊瑚红：`#F06445`

日历和便签保留各自现有预设色的视觉含义，但预设值改为对应 HEX。每个模块维持当前默认色，只把默认值改为对应 HEX。

TypeScript 使用表达已校验 HEX 的字符串类型或统一颜色工具边界；Rust 模型继续通过字符串序列化，但命令校验只接受 `#RRGGBB`。

### 2.2 数据迁移

数据库升级时执行幂等迁移：

- 日历：`blue`、`red`、`green`、`yellow` 转为对应 HEX。
- 便签：`yellow`、`blue`、`green`、`purple` 转为对应 HEX。
- 看板：`primary`、`success`、`info`、`warning`、`danger` 转为设计 Token 对应 HEX。
- 已是合法 HEX 的值规范化为大写。
- 无法识别的历史值回退到对应模块默认颜色，确保数据可继续读取。

迁移必须可以重复执行，第二次及之后运行不改变结果。迁移完成后，读取、写入和渲染只处理 HEX。

## 3. 共享颜色选择器

新增一个跨模块复用的 `ColorPicker`。组件接收当前值、模块预设颜色、禁用状态及变更回调，不承担业务保存。

### 3.1 交互

- 展示当前模块的预设颜色。
- 末尾提供“自定义”入口，使用原生 `<input type="color">` 打开系统色板。
- 用户选色后立即选中该颜色；取消系统色板时保持原值。
- 不在界面显示 HEX 文本值。
- 自定义选中态只显示颜色色块和“自定义”文案。
- 展示全局最近使用的自定义颜色，最多 8 个，最新在前。
- 重复使用已有颜色时将它移到最前，不产生重复项。
- 模块预设色不写入最近使用列表。
- 最近使用颜色跨日历、便签和看板共享，并在应用重启后保留。

### 3.2 表单与无障碍

预设、最近及当前自定义颜色都通过原生 Radio 表达单选关系，并套用以下结构：

```html
<label class="form-check form-check-custom form-check-solid">
  <input class="form-check-input" type="radio">
  <span class="form-check-label">颜色名称</span>
</label>
```

系统色板触发器具有清晰的可访问名称。Radio 组使用 `<fieldset>`、`<legend>` 和组内唯一 `name`。焦点、选中、禁用状态即时切换，不增加任何动效。

## 4. 最近颜色持久化

在应用设置中新增全局 `recentColors` 字段，值为规范化 HEX 数组。

- 应用读取设置时过滤非法项、去重并截断为 8 项。
- 用户选择自定义色并成功保存对应业务数据后，才更新最近颜色，避免取消业务弹窗也污染历史。
- 更新算法为：规范化 → 移除已有同色 → 插入首位 → 截取前 8 项。
- 设置缺失或数据异常时回退为空数组，不阻止应用启动。

如果业务保存成功但最近颜色设置更新失败，业务保存结果仍保留；界面沿用现有通用错误处理方式记录或反馈设置更新失败，不回滚已经保存的业务实体。

## 5. 自定义颜色渲染

新增独立颜色工具，负责：

- 验证和规范化 `#RRGGBB`。
- 将 HEX 转换成 RGB。
- 根据原色生成与设计系统相符的浅色背景。
- 根据背景相对亮度选择达到可读对比度的深色或白色文字。

日程块、便签、优先级徽标和标签使用“浅色背景 + 可读文字/强调色”。泳道圆点直接使用原色。组件通过受控的内联 CSS 自定义属性传递原色、浅背景和文字色，不按自定义值动态生成 CSS 类。

颜色仍是辅助信息；重要状态继续通过文字、标签或图标传达，不能只依赖颜色。

## 6. 看板界面调整

### 6.1 泳道标题

泳道 Header 顺序改为：

> 颜色点 → 泳道名称 → 数量 → 新增按钮 → 泳道三点菜单

名称优先显示并可在空间不足时省略；数量紧随名称，保持固定可读。新增按钮和泳道菜单保留。

### 6.2 任务卡片

- 完全移除任务卡片右上角三点菜单和关联菜单项。
- 优先级徽标继续显示在右上区域。
- 点击任务标题继续打开编辑弹窗。
- 删除操作继续位于编辑任务弹窗。
- 拖拽排序和跨泳道移动保持不变。
- 不增加替代菜单或额外操作按钮。

### 6.3 Radio 与 Checkbox

看板泳道、优先级、标签颜色 Radio，以及任务标签、协作人 Checkbox，全部遵循 `design.md` 的 Good Custom Solid 规范：

- 保留原生 `<input>`，并使用 `appearance: none`。
- 尺寸 `28×28px`，`flex-shrink: 0`。
- 未选中背景 `#DAD3C3`；选中背景 `#4FC9DA`。
- Checkbox 显示白色对勾；Radio 显示白色实心圆点。
- 标签间距、字体、`focus-visible` 和 disabled 状态与系统控件一致。
- 移除看板专属 `20×20px`、`accent-color` 和浏览器默认外观。

## 7. 数据流与错误处理

1. 业务弹窗从实体或默认值初始化 HEX 颜色。
2. `ColorPicker` 输出规范化 HEX。
3. 表单提交前由前端颜色工具校验。
4. Repository 将 HEX 发送给 Tauri 命令。
5. Rust 后端再次校验并写入数据库。
6. 业务保存成功后，若使用的是非预设自定义色，则更新全局最近颜色。
7. UI 使用颜色工具计算渲染变量。

非法颜色由后端返回现有格式的 `validation_error`，字段为 `color`。前端在对应颜色选择器附近显示错误并保持弹窗打开。系统色板取消不触发变更。无效历史最近颜色被静默过滤。

## 8. 测试策略

实现遵循 TDD，每项行为先编写会因功能缺失而失败的测试。

### 8.1 TypeScript 单元测试

- HEX 校验与大写规范化。
- HEX/RGB 转换、浅色背景计算、文字对比色选择。
- 最近颜色去重、移到首位和最多 8 项。
- 各模块旧默认值转换后的表单行为。

### 8.2 组件测试

- `ColorPicker` 展示预设、自定义入口和最近颜色。
- 不显示 HEX 文本。
- 自定义选择和取消行为正确。
- Radio 均使用 Good Custom Solid 结构。
- 看板 Checkbox 同样使用统一结构。
- 禁用和键盘焦点语义保留。

### 8.3 模块测试

- 日历、便签、泳道、优先级和标签保存 HEX。
- 任务卡片不存在三点菜单。
- 泳道名称在数量之前。
- 卡片点击编辑、弹窗删除及拖拽仍可用。
- 自定义颜色样式变量正确应用。

### 8.4 Rust 测试

- 各业务命令接受合法 HEX、拒绝非法值。
- 旧颜色映射迁移正确。
- 迁移重复执行结果不变。
- 最近颜色设置可持久化，异常内容可安全清理。

### 8.5 端到端测试

- 在一个模块保存自定义色后，其他模块可看到该最近颜色。
- 重载应用后最近颜色仍存在。
- 自定义颜色在日历、便签和看板正确渲染。
- 看板任务卡无三点菜单，泳道菜单仍存在。
- 看板拖拽、编辑与删除流程无回归。

## 9. 设计约束

所有新组件和样式严格遵循根目录 `design.md`：使用已有 Token、15.2px 默认圆角、Good Custom Solid 表单控件、静态交互状态，并禁止 `transition`、`animation` 或其他动效。此次不进行与颜色和看板需求无关的重构。
