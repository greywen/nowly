# Nowly 实时时钟设计

## 背景

当前 `App` 在 React 渲染期间直接执行 `new Date()`，但没有任何时钟状态或定时更新。切换为壁纸模式会触发一次渲染，因此顶部时间停留在切换发生的那一分钟；之后没有其他状态变化时，React 不会重新渲染。该问题同时影响顶部日期、今日摘要以及日历中的“今天”状态。

## 目标

- 顶部时钟按分钟实时更新，并尽量与系统整分钟边界对齐。
- 跨过午夜后同步更新日期、今日摘要和日历“今天”状态。
- 系统休眠恢复、页面重新可见或窗口重新获得焦点后立即读取系统时间并校准。
- 保持分钟级刷新，不增加无显示价值的秒级渲染。
- 不修改现有视觉样式和桌面壁纸嵌入机制。

## 方案

新增独立的 `useCurrentTime` Hook，由它提供响应式的当前系统时间。

Hook 初始化时以 `new Date()` 建立状态。每次调度都计算距离下一个整分钟的剩余毫秒，并使用一次性定时器在该边界读取新的 `Date`；更新后重新计算下一次边界，而不是永久运行固定的 `setInterval(60000)`。这样可减少初始化偏移和长期漂移。

Hook 监听以下浏览器生命周期事件：

- `document.visibilitychange`：页面恢复可见时立即同步；
- `window.focus`：窗口重新获得焦点时立即同步。

每次同步均直接读取当前系统时间，不在旧状态上累加一分钟，因此可以正确恢复休眠期间经过的时间，也能响应用户手动修改系统时间或时区。同步后取消旧定时器并按新的系统时间重新对齐下一分钟。

组件卸载时清除定时器并移除全部事件监听，避免重复调度和泄漏。

## 组件与数据流

1. `useCurrentTime` 持有当前 `Date` 状态并负责调度与生命周期校准。
2. `App` 调用 Hook，替代渲染期间无状态的 `new Date()`。
3. `App` 继续使用现有 formatter 生成顶部时间和日期。
4. 同一个响应式时间用于计算本地 `todayIso`。
5. `todayIso` 变化时，今日事件摘要与日历“今天”标记随 React 渲染自动更新。

该改动不改变 `DesktopShell` 的接口，也不要求 Rust/Tauri 后端推送时间。

## 边界与错误处理

- 系统定时器可能因休眠或后台节流延后；回调执行时读取真实系统时间，因此不会累积误差。
- 分钟边界延迟使用当前毫秒和秒数计算，并保证延迟为正值。
- 页面隐藏时不要求持续精确渲染；恢复可见时立即校准。
- 重复的可见性或焦点事件会替换当前定时器，只保留一个有效调度。
- 本功能不引入网络、存储或后端错误路径。

## 测试策略

遵循测试驱动开发，先增加会失败的自动化测试，再实现 Hook。测试使用可控系统时间和伪定时器，覆盖：

1. 初始值来自当前系统时间；
2. 到达下一个整分钟时更新时间；
3. 跨过午夜后提供新日期；
4. 页面恢复可见时立即读取跳变后的系统时间；
5. 窗口获得焦点时立即同步；
6. 重新校准不会留下多个有效定时器；
7. 卸载后定时器和监听不再触发更新。

完成后运行相关 Vitest 测试、完整前端测试和构建检查。

## 非目标

- 不显示秒数。
- 不使用 Rust 后端定时事件。
- 不轮询业务数据。
- 不修改日期、时间或摘要的视觉设计。
- 不改变 WorkerW、托盘或窗口模式生命周期逻辑。
