# 专注计时全屏与统计设计

## 1. 目标与范围

将现有专注计时扩展为可靠的全局功能：用户可使用固定预设或自定义分钟数开始专注；运行中的计时器在进入壁纸模式时自动以大号文字叠加在实际桌面壁纸上；自然完成后发送系统通知；完成与主动中断会话形成专注记录，并在模块迷你趋势和统计弹框中展示。

本次范围包括：

- 全局共享计时状态与原生后台协调。
- `25 / 15 / 5` 分钟预设及 `1–720` 分钟自定义时长。
- 壁纸层全屏专注界面及手动全屏入口。
- 自然完成系统通知。
- 完成/中断记录、7 天迷你趋势、完整统计弹框。
- 近 7 天、近 30 天、近 12 个月统计。
- 小尺寸模块自适应。
- 中英文文案、可访问性、自动化测试。

本次不包括声音提醒、休息计时、番茄循环、目标分类、云同步和导出报表。

## 2. 设计约束

所有界面严格遵守根目录 `design.md`：

- 白色表面、暖灰分区、青绿色主操作、低对比边框和 `15.2px` 标准圆角。
- 普通卡片无阴影；统计弹框使用规范 `shadow-lg`。
- 操作按钮保持 `40px` 高，键盘焦点使用青绿色 `4px` focus ring。
- 使用项目既有 Lucide 线性图标，不混用图标体系。
- 不使用渐变作为应用背景。视觉稿中的渐变仅模拟用户实际桌面壁纸。
- 禁止所有动画、过渡、淡入淡出、位移、缩放及加载旋转；状态即时切换。
- 状态含义同时使用文字、图标或图例表达，不仅依赖颜色。

## 3. 用户界面与交互

### 3.1 专注计时模块

模块包含：

1. 标题与“查看统计”入口。
2. 大号等宽倒计时和当前状态说明。
3. `25 / 15 / 5` 分钟预设及“自定义”入口。
4. 开始/暂停/继续、重置和全屏操作。
5. 近 7 天累计分钟数和迷你折线趋势。

固定预设不会被自定义时长替换。最近一次自定义分钟数持久化，仅作为下次打开自定义入口时的默认值。输入只接受 `1–720` 的正整数；无效输入显示危险色边框、图标及说明。

修改时长或重置活动会话会先请求确认。若已产生至少 1 秒有效专注时间，确认后记录为中断；未产生有效专注时间则不记录。计时尚未开始时全屏按钮禁用并具备可访问说明。

### 3.2 模块自适应

模块根节点建立 CSS containment，并用 Container Query 根据模块自身可用尺寸适配，不依赖视口宽度：

- 空间充足：显示完整计时、操作区、累计数据与迷你折线图。
- 宽度较窄或高度不足：优先隐藏迷你折线图，保留累计分钟数与“查看统计”。
- 进一步缩小：预设按钮紧凑换行，但不把正文字号缩至规范之外，不降低操作按钮 `40px` 高度。
- 倒计时、状态和核心控制始终保留。
- 隐藏图表使用即时 `display` 切换，无折叠或淡出。

实际 Container Query 断点在实现时依据现有 `focusTimer` 最小网格尺寸，以“不溢出、不遮挡核心操作”为验收条件固定下来，并由组件与 Playwright 用例覆盖。

### 3.3 壁纸全屏专注层

倒计时直接叠加于用户实际桌面壁纸，不生成应用渐变背景。大号轻字重数字使用 `font-variant-numeric: tabular-nums`，并使用静态文字阴影保障复杂壁纸上的可读性。

自动显示条件为：窗口刚切换为 `wallpaper` 且当前会话处于 `running`。未开始、暂停或已完成状态不会因进入壁纸模式自动显示。若用户在本轮会话中手动退出全屏，本轮不会再次自动拉回；再次点击“全屏”或开始新会话后可重新进入。

前台模式中，`running` 或 `paused` 会话可手动进入全屏层。全屏层提供：

- 暂停/继续。
- 退出全屏（仅退出沉浸界面，计时继续）。
- 结束专注（确认后终止并按规则记录中断）。

`Esc` 等同“退出全屏”。壁纸模式既有双击返回前台行为继续保留，计时不中断。

控制区初次进入时显示；鼠标离开且焦点不在控制区时即时隐藏，鼠标再次移动或键盘 `Tab` 导航时即时显示；触屏点击空白处切换。不得使用淡出、延迟淡出或其他动效。

自然完成后留在全屏层，静态显示“专注完成”，提供“重新开始”和“退出专注”。

### 3.4 统计弹框

点击“查看统计”、累计数据或迷你图打开标准统计弹框。弹框支持：

- 近 7 天：按本地自然日聚合。
- 近 30 天：按本地自然日聚合。
- 近 12 个月：按本地自然月聚合。

弹框展示总专注时长、完成次数、中断次数、完成率及折线图。主折线表示实际专注时长；完成与中断通过明确图例、文字和数量表达。无数据时显示静态空状态。弹框遵循项目既有 Dialog 的焦点捕获、Esc、关闭按钮与焦点归还行为。

## 4. 状态架构

### 4.1 唯一状态源

新增应用级 `FocusTimerProvider` / `useFocusTimer`，作为普通模块、全屏层和统计入口的唯一状态源。现有 `FocusTimerWidget` 不再拥有独立 interval 状态。

状态机：

```text
idle → running ↔ paused
running → completed
running/paused → interrupted → idle
completed → idle 或 running（重新开始）
```

非法或重复命令保持幂等，不创建第二个活动会话。核心状态包括：

- 会话 ID。
- 当前状态。
- 计划秒数与剩余秒数。
- 首次开始的墙钟时间。
- 当前运行区间的单调时钟起点。
- 先前运行区间累计有效秒数。
- 当前是否显示全屏层。
- 本轮是否已手动退出全屏。
- 终态记录保存状态。

倒计时显示不以“每秒减一”作为真值，而依据累计运行区间和当前单调时钟计算。UI 的每秒 tick 仅触发重绘。暂停期间不计入有效专注时间。系统睡眠期间，运行状态按实际经过时间计入；暂停状态不计入。

### 4.2 React 与 Tauri 边界

React Provider 负责：

- UI 状态和状态机操作。
- 显示剩余时间。
- 普通模块、全屏层和统计数据加载。
- 将终态记录提交 Repository。

Tauri 内存协调器负责：

- 接收开始、暂停、继续、取消命令。
- 主窗口隐藏至托盘时继续等待完成。
- 使用原生/单调计时判断自然完成。
- 到点发送系统通知并发出 `focus-session-completed` 事件。
- 仅在内存中保留当前活动会话，不持久化未完成状态。

React 与原生协调器使用同一个稳定会话 ID。自然完成事件包含生成记录所需的会话快照。前端存在时立即幂等写入；前端随后恢复时可从协调器取得尚未确认写入的已完成快照并重试。

### 4.3 生命周期语义

- 关闭主窗口但应用仍驻留托盘：继续计时，到点通知并正常记录。
- 切换壁纸/前台模式：会话继续。
- 彻底退出应用进程：当前未终结会话直接丢弃，不记录、不恢复。
- 下次启动：不恢复活动倒计时，不补发通知。
- 应用崩溃：等同彻底退出，当前活动会话不记录。

应用的显式退出路径须先清除原生协调器中的活动会话，但不能创建中断记录。

## 5. 会话记录与统计

### 5.1 数据模型

新增独立数据库表，不复用模块 JSON 字符串状态：

```ts
type FocusSessionStatus = 'completed' | 'interrupted';

type FocusSession = {
  id: string;
  plannedSeconds: number;
  focusedSeconds: number;
  status: FocusSessionStatus;
  startedAt: string;
  endedAt: string;
  createdAt: string;
};
```

`id` 具有唯一约束，以保证自然完成事件重放或恢复重试不会重复写入。秒为存储与聚合基础单位。

记录规则：

| 场景 | 记录 | 状态 | 通知 |
|---|---|---|---|
| 自然完成 | 是 | `completed` | 是 |
| 用户结束且有效专注 ≥ 1 秒 | 是 | `interrupted` | 否 |
| 用户结束但有效专注为 0 | 否 | — | 否 |
| 重置/改时长且有效专注 ≥ 1 秒 | 是 | `interrupted` | 否 |
| 退出全屏但继续计时 | 否 | — | 否 |
| 彻底退出进程 | 否 | — | 否 |
| 关闭窗口驻留托盘 | 继续 | — | 到点通知 |

自然完成与用户结束竞态由原生协调器首次确认的终态决定，一个会话只能得到一个终态。

### 5.2 时间与聚合

数据库保存 ISO 时间戳。报表按照当前用户本地时区、以 `endedAt` 所在日期/月归档；跨午夜会话不拆分。近 7/30 天补齐无记录日期为零，近 12 个月补齐 12 个自然月。

底层保留秒数，汇总显示时统一转换为分钟；总时长和每个点采用一致的取整规则（最接近的整数分钟），Tooltip/可访问说明可显示精确到分钟的结果。完成率为 `completed / (completed + interrupted)`；分母为零时显示 `0%`，不显示 `NaN`。

### 5.3 Repository

`NowlyRepository` 新增：

```ts
createFocusSession(record): Promise<FocusSession>;
listFocusSessions(range): Promise<FocusSession[]>;
getFocusStatistics(range, granularity): Promise<FocusStatistics>;
```

```ts
type FocusStatistics = {
  totalFocusedSeconds: number;
  completedCount: number;
  interruptedCount: number;
  completionRate: number;
  points: Array<{
    period: string;
    focusedSeconds: number;
    completedCount: number;
    interruptedCount: number;
  }>;
};
```

聚合优先在数据库层执行，不向前端加载全部历史。迷你图请求近 7 天统计；弹框按选定周期请求。范围边界由前端按本地日期生成明确起止时间并传给后端，避免 SQLite 隐式时区解释。

## 6. 系统通知

自然完成后由 Tauri 原生层调用系统通知：

- 标题：“专注完成”。
- 正文：“你已完成 {分钟} 分钟专注，休息一下吧。”
- 自定义时长按计划时长显示。
- 每个会话 ID 最多通知一次。

首次需要时请求系统通知权限。权限被拒绝或发送失败不阻断自然完成、完成界面和统计写入。主动中断、暂停、重置和彻底退出均不通知。

点击通知时显示并聚焦 Nowly 主窗口；若会话仍处于完成状态则保留完成界面，不自动打开统计弹框。

## 7. 错误处理与并发

- 完成记录写入失败：保留已完成快照，显示静态错误和“重试保存”；稳定 ID 保证重试幂等。
- 中断记录写入失败：完成确认后保持可恢复错误状态，不伪装为已保存；允许重试。
- 统计加载失败：计时可继续；迷你图和弹框各显示静态错误及重试按钮。
- 通知失败：不改变会话终态，不阻塞记录。
- 命令处理中禁用重复操作。
- 原生协调器负责裁定自然完成与主动终止竞态；Provider 接受最终快照，不自行覆盖终态。
- UI interval 被限频时，下一次重绘从单调时间重新计算，不累积漂移。

## 8. 可访问性与国际化

- 所有新增可见与可访问文案进入现有 `zh-CN` / `en` 翻译系统。
- 大号倒计时使用 `role="timer"`；避免每秒打断屏幕阅读器，状态变化（暂停、完成、失败）使用独立礼貌播报区。
- 图表提供文本摘要和每个数据点的可访问名称，不要求用户仅靠 SVG 读取。
- 图表周期切换使用按钮组并表达当前选中状态。
- 自定义时长错误与输入通过 `aria-describedby` 关联。
- 全屏控制在键盘导航时立即可见，焦点不进入隐藏元素。
- 完成/中断同时使用文字或图标表达，不只依赖颜色。

## 9. 测试与验收

### 9.1 TypeScript 单元测试

- 合法状态转换、非法与重复命令。
- 暂停不计时、继续累计、UI 限频校正。
- 自然完成和主动中断快照。
- 彻底退出不生成记录。
- 会话 ID 幂等。
- 自定义时长 `1`、`720` 边界及非法输入。
- 7 天、30 天、12 个月聚合、零点补齐、完成率。
- 本地日期和跨午夜归档。

### 9.2 React 组件测试

- 模块开始、暂停、继续、重置、改时长和全屏。
- 模块与全屏层共享状态。
- 仅运行状态进入壁纸时自动全屏。
- 手动退出后本轮不自动拉回。
- Esc、双击返回前台和结束确认语义。
- 鼠标、触屏与键盘控制区显示。
- 完成、保存失败、统计失败和空状态。
- 统计周期切换、图表文本摘要、焦点归还。
- 小容器隐藏迷你折线图但保留累计数与统计入口。

### 9.3 Rust/Tauri 测试

- 托盘状态继续计时。
- 自然完成只通知一次并发出一次完成事件。
- 主动中断不通知。
- 权限拒绝不影响终态。
- 显式退出清除内存会话且不持久化。
- 数据库迁移、唯一约束和三种聚合查询。
- 完成/中断竞态只接受一个终态。

### 9.4 Playwright 验收

- 开始计时后进入壁纸模式，出现全屏大号倒计时。
- 暂停、恢复、退出全屏和返回前台后状态一致。
- 完成后显示完成界面并更新统计。
- 提前结束形成中断记录。
- 三种周期正确切换并补齐空区间。
- 最小模块尺寸不溢出，迷你图被隐藏，核心功能和统计入口保留。
- 页面无整体滚动溢出。
- 新增 UI 无 `transition` 或 `animation`，并复用 `design.md` 的颜色、圆角、边框、字号、按钮高度和焦点状态。

## 10. 实现边界

建议按以下独立边界实施：

1. 纯计时状态机与时长验证。
2. Focus Repository 数据模型、迁移及统计聚合。
3. Tauri 内存协调器与系统通知。
4. 全局 FocusTimer Provider。
5. 自适应专注模块与迷你趋势。
6. 壁纸全屏层。
7. 统计弹框与折线图。
8. 生命周期集成、国际化及端到端验收。

这些单元通过稳定的会话 ID、明确的终态快照和 Repository 接口通信，避免 UI、计时、通知与数据库彼此直接耦合。
