3. Google 用户敏感数据保护机制

{{productName}} 使用 OAuth 2.0 Authorization Code + PKCE 授权流程，并使用随机 state 参数防止请求被替换。授权结果只返回用户设备上的临时 loopback 回调监听器。

授权、令牌交换和 Google Calendar API 请求均通过 HTTPS（TLS）传输，并且目标仅限 Google 的授权、令牌、身份和 Calendar API 端点。

{{tokenStorageDescription}}访问令牌和刷新令牌在写入本地数据库前即完成加密，密文与当前 Windows 用户账户绑定，只会在应用后端发起已授权 Google API 请求时解密。OAuth 令牌不会被有意写入日志、不会暴露给应用界面，也不会发送到开发者运营的服务器。

{{calendarStorageDescription}}本地日历缓存只能通过用户自己的 Windows 账户和 Nowly 应用功能访问。用户应保护 Windows 账户、及时更新操作系统和 Nowly，并在设备丢失或与他人共用时断开账户。

可选联网能力与本地优先

Nowly 是你的 Windows 个人工作桌面，本地优先不等于全部功能离线。除授权日历同步外，可选 AI 助手会把输入、对话历史和用户允许的上下文发送到用户配置的模型服务；启用外部日历读取权限时，上下文可能包含本机缓存的 Google、Microsoft 或 ICS 事件。AI 对外部事件只读，不能通过 AI 修改远端日历。不要将未获授权的敏感资料交给模型服务，并核对该服务的数据保留政策。

Google 用户数据不得用于训练、开发或改进通用模型；使用者应选择与有限使用要求一致的服务配置。Nowly 的更新检查会请求 GitHub 发行信息。网站无分析脚本，但托管服务可能生成普通访问日志。本地数据包含数据库、附件文件与截图 PNG；桌面原生集成和可选外部服务不由本公开网站执行。
